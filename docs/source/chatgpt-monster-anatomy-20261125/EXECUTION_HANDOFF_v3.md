# 実行引き継ぎ v3 — 生物として成立するモンスター

利用者の「実行」を受けた作業指示。基準はv0.26.0 / `1e078bfce1e68f287ae577cf41d2fe5bafb94afa`。コード・実行データ・検証・公開は`AGENTS.md`の分担に従ってClaudeが担当する。

## 目標

採用済みガルドロスを最初の完成基準とし、胸と骨盤の厚み、関節の肉の量、硬い岩板と柔らかい皮膚の接合、支持足への体重移動、独立した顎・眼・趾を成立させる。各系統へはこの基準が通ってから展開する。

一般リグの顎、四足/二足の通常歩行の接地、一般19体の技/睡眠中の部位追従は、v0.25.0で導入済みなので作り直しの対象にしない。現在の完了範囲と残る例外は `current_status_v026.md` を正本とする。

## M1: 骨番号を壊さず、親子関係を変える

現行は `src/render/galdrosRig.ts` の `ROOT`〜`PLATE`定数と、`LEG + i * 4`、`PLATE + i`の計算に依存している。Boneの生成ループも、親が先に作られることを前提にしている。

1. 現行のrest支点・parent・旧番号をソースから取得し、変更前の基準として保存する。復旧JSONの3桁支点を精密な正本として上書きしない。
2. 旧番号0〜52と設計名の対応を作る。79の配列順を旧番号の代用にしない。
3. 全Boneを先に作り、その後で親子を接続する。新肩甲部を旧上腕の親にする時も、構築順で失敗しないようにする。
4. 親を付け替えてもactor空間の基準姿勢を維持する。親が回転したbindを使う場合は、親bind逆行列で子の基準変換をlocalへ戻す。
5. 骨の対応が確定してから、関節軸・可動域・ウェイト・補正形状を設定する。骨名を追加しただけで完成にしない。

前脚の前向き4趾はpalm、けづめはwristへ。前腕と下腿のtwist補助はIKの主鎖へ挿入せず枝にする。後脚3制御群は趾の変形領域で、実趾数を3本にする指定ではない。左右胸郭の分離は現行 `B[RIBS].scale` とウェイトの両方を更新する。

## M2: 肉・皮膚・岩板の接合

- 胸郭・骨盤の正面/背面の厚みを先に決める。ガルドロスのゲーム全長は約5.8mを基準にし、図鑑の8.5mへ無断で拡大しない。
- 肩・肘・股・膝の皮膚は連続した面として曲げ、関節内側の潰れと外側の引き伸ばしを補正する。
- 岩板15枚は硬さを保つ。各板の骨を持つことと、材質やdraw callを15分割することは同義ではない。
- 顎は口腔の厚み・上顎との隙間・舌との関係まで確認する。目は視線とまぶたを独立させる。
- 頂点構成を変えたらAO・UV・アトラスも制作元から更新する。現行の頂点番号に依存したAOだけを持ち越さない。

## M3: 同じ姿勢から、見た目と判定を作る

固定60Hz tickと、既存shapeTrackを正本とする移行段階を維持する。表示側の`dt`、視線の向き、前フレームの揺れを戦闘の入力にしない。

現行の一般部位追従は `tests/creature-motion.test.ts` の生成経路、`public/data/follow/`、`src/game/follow.ts` を使う。6tick間隔・cm整数・5cm未満の差を省略する現在の仕様を確認し、精度が足りない箇所は実測と比較して調整する。生成物だけを手編集しない。

ガルドロスはこの一般生成経路の対象外で、`tests/follow.test.ts`もfollow無しを前提にしている。専用リグのポーズ評価を固定tickで再現可能にしてから、必要な部位の表を生成する。

転倒・怯みの姿勢は、向きと経過tickを戦闘側の確定した状態に持たせる。表示側だけが決める転倒方向へ判定が後追いする構成にしない。現行 `monsterShapes()` は `!severed` の時だけfollowを使うため、切断後の分岐を明示的に追加する。

### 支持と攻撃の両立

接地は `swing → touchdown → stance → toe_off` の4状態で扱う。支持鎖へ影響する被弾・視線は最終IK前に入れるか、後段で接地を再投影する。攻撃中は採用済み軌道と支持条件を同時に満たす。

前脚叩きは現行120tick、予備動作 `[0,48)`、攻撃 `[48,54)`、回復 `[54,120)` を維持したまま、荷重移動→脚の引上げ→落下→衝撃吸収→支持回復を割り当てる。既存の時刻や威力を新モデル化に便乗して変更しない。

### 尾切断とsocket

現行CUT=4、切断境界のz=-2.22。切断後に残るtail_04側から境界へ切断面socketを置き、無効になるtail_05以降を切断後判定の正本にしない。切断後用の `tail_strike_cut` を明示する。

前回JSONの12socketの完全な定義は今回のPDF表からは復旧できない。正式モデル化の入口で、次の欄を持つsocket台帳を再確定する: 名前、用途、親骨、actor基準位置、bind-local変換、forward/up、参照する技/部位、破壊/切断時の有効性と切替先。PDF本文にある制約を保ち、失われた詳細を既存値として推測採用しない。

## M4: 種と幼体の差を保持する

オルグラスは六歩脚＋鋏2本、ヴェリトは八歩脚、アシュレイアの短翼は継続飛行を前提にしない。テンガロは脚を収納して輪になってから転がる。長胴2種では腹の接触と短肢/ひれ足の支持を分ける。各種の細部は43ページ原本を参照する。

幼体は親の一律縮小にしない。ヒナサルヴの短肢とfinは同じ2対の成長器官として整理できるかを図で確定する。ヴェリトの機能的な管口2と表示上の枝4を区別する。ヌマポロンの幼水圧嚢が体内なら、皮膚の変形としてどう見せるかを確定する。修正済みのチルミカナ・ユルテピカ・キリサーヴを欠落修正として再発注しない。

## 採用・検収の扱い

原画のある86種のうち、採用済み基準はガルドロス。その他の原画の採用待ち状態を勝手に変えない。全86種台帳の現在値はimplemented20 / art66で、artは採用を意味しない。

既存の15検査成功は新しいモデルの合格証ではない。制作後は支持足の滑り、地面への貫通、攻撃と部位の位置差、切断後の形状、関節の体積、甲殻の干渉を数値と通常速度映像で照合する。重い一体から始め、複数種・複数体・iPhoneへ順に範囲を広げる。

骨数・LOD・可動域・許容誤差の数値は設計案。実測で成立しない値を達成済みにしない。採用した変更は本体の生成元と文書へ反映し、掲示板に取り込み範囲と未完了範囲を記録する。
