対象：`kamamon/Kari` / 霧境の狩人 – VEILBOUND HUNTERS  
現行照合：main `0925487b686473e1a4d7e45fdc63449ef3a7d2ec`、v0.34.0

## 1. Claudeが最初に理解すること

今回の依頼は「基本的には2Gのハンターの動きやモンスターのモーション、武器や防具のシステム、フィールドの形・地形・デザインを踏襲したい。モンスター・武器・ハンターのデザインはオリジナルで、その他は限りなく近づける」というもの。

**PSP日本版『モンスターハンターポータブル 2nd G』を、操作・動作の構成・戦闘の間合い・装備の組み方・狩場の構造の主基準として採用する。** 調査を紹介文として取り込むだけで終えず、本パッケージの要件を順番に実装する。近づける対象は、見た目の懐かしさだけでなく「何を入力できるか」「いつ動けなくなるか」「どの姿勢から避けるか」「どこで反撃するか」「どの準備が必要か」という判断の構造である。

既存の調査受領 D-110 と `docs/research-mh-notes.md` の「資料であって採用した仕様ではない」は、以前の依頼に対する位置付けである。今回の指示で、ここに記す範囲を**採用する仕様**へ進める。過去資料は履歴として残し、最新のboard・handoff・specには今回の採用方針と実装状況を追記する。資料の移動と受領報告だけを完了にしない。[K0]

外形はKariの採用済みデザインを使う。ハンターの顔・髪・体型、衣服、防具・武器の造形、モンスターの外形・器官・名称、里と狩場の固有の世界観はオリジナルのまま制作する。動作はKariの骨格と武器寸法へ作り直す。原作のメッシュ、アニメーションデータ、UI画像、音声や背景テクスチャの取り込みを前提にしない。

## 2. 何を、どこまで近づけるか

| 領域 | 採用する設計 | 完成時にできていること |
| --- | --- | --- |
| ハンター | 納刀と抜刀、武器ごとの歩き・回避、攻撃の連係窓、溜め、防御、止まって行う道具動作 | 出した技の重さと、次の行動を選べる時点が姿勢・入力・判定で一致する |
| モンスター | 足を踏み替える向き直り、技の方向確定、予備動作、突進の制動、反撃できる戻り | 横へ回った結果が読み合いへ反映され、全身が滑って永久追尾する攻撃にならない |
| 武器 | 2Gに対応する11系統の役割と固有状態 | 各系統に独立した入力・資源・間合い・生産経路があり、形の違う同じ攻撃にしない |
| 防具・技能 | 5部位、正負の技能点合算と発動閾値、装飾枠、近接／射手の適合 | 一式、混成、装飾の組み方で発動技能と不利な技能が変わる |
| 生産・成長 | 素材持帰り、横に分かれる武器派生、防具の防御強化、重要依頼と昇級 | 狩りの成果で次の狩りの準備が変わり、装備選択と習熟で成長する |
| フィールド | 番号付きエリア、広場と狭路、段差・岩棚・登攀、採集の枝道、大型の移動路と巣 | エリアの形、入口の向き、遮蔽物、回復場所、追跡経路が判断に影響する |
| 画面・カメラ | 手動視点と背後戻し、安定した体力・スタミナ・武器資源・道具・地図 | 足元・攻撃部位・退路が読め、追跡の情報量が道具や視認に応じて変わる |

MH3の水中戦・大型の疲労と捕食、MHP3rd以降の武器派生、後年の乗り・自由な空中連係・移動回復を、2Gへ近づける改修として追加しない。2G for iOSのターゲットカメラもPSP版の基準と混同しない。[R1–R3]

## 3. 現行から必要な変更

以下は固定SHAのコード・データを読んだ差分であり、実機試遊での評価ではない。詳しい変更先は01〜05に記す。

| 現行確認 | 今回の改修 |
| --- | --- |
| 護刃のパリィ、長尖槍のカウンター、太刀の兜割り、双剣の命中蓄積による勢い | 2G基準の通常ルートへ置き換える。旧技は移行記録として扱う |
| 環弓の前方範囲からの自動部位照準、道具1押しで自動納刀後に自動使用 | 手動照準と、納刀後に道具を使う独立した判断を標準にする |
| 通常歩行の世界接地はあるが、攻撃中の支持足は別扱い | 攻撃の接地区間・移動曲線・刃の軌道・判定窓を一つの時刻で制作する |
| モンスターの三段階攻撃・追尾打切り・怒り・弱り・転倒は存在する | 向き直りの足運び、制動、転倒中の部位追従、巣で寝る条件を詰める |
| 技能は部位ごとの点をLvへ直結。装飾枠・複数個体所持がない | 正負の合算閾値・装飾品・装備個体・保存移行を実装する |

| 地図は格子配置の矩形表示。大型の所在エリアが常時分かる | 地理的な輪郭のミニマップと、視認・目印による追跡へ移す |
| 敵HPと部位数値は検証表示に分離済み | 検証用表示のまま維持し、通常画面に内部HPや捕獲確率を常設しない |

## 4. 標準仕様と既存資産の扱い

動作・装備・地形を `classic_hunt_v1` という一つの設計版で追跡する。名称は内部管理用で、プレイヤー向けの毎回の選択画面を増やす必要はない。新規の標準体験はこの仕様とする。旧仕様との二重実装を恒久的な代替ゴールにせず、旧保存・旧リプレイの互換と移行を版で扱う。

既存のロックオン・自動照準・自動道具連係は、残すなら個別の操作補助設定にする。既存利用者の設定を通知なく消さない。手動の標準で狩りが成立したことを確認してから補助を比較し、視点追従と攻撃の命中補正を別設定にする。左利き・ボタンの大きさと配置・タッチ対応は継続する。

次はKariで既に採用した差として保つ。2Gそのものの仕様という表示は付けない。[K1–K4]

| 維持するもの | 移行・制作上の扱い |
| --- | --- |
| 初級・中級・上級・極級の4等級と恒久ID | 進行、素材、既達成の解放を維持。装備強化段・依頼難度・進行段階は分ける |
| 風・霧を含む6属性と既存世界観 | 弱点・耐性の部位表へ接続し、名称や種類を原作に揃えるため削除しない |
| 離脱中の大型には走って追いつけないという以前の要望 | 退避速度を維持し、弱りは歩様と退避前後の動作で見せる。低速の無抵抗逃走へ戻さない |
| 里の0m／-3mの段と階段、残りの段の計画 | 里を平面へ戻さない。狩場の地形契約と共存させる |
| 採用済みハンター・装備・環境原画、53骨のガルドロス実装 | 有効な資産を使い、未実装の骨や未採用の外観は制作状態を明記する |
| 60Hzの固定simulationと保存競合対策 | 原作映像のfpsに合わせて計算周期を落とさない。描画負荷と判定周期を分ける |

動きへ寄せるために恒久の武器IDを振り直さない。所有数、強化、素材、通貨、装備セット、達成記録、外見を移行し、未知の保存欄も保持する。schemaの次番号は着手時の最新mainで確保し、現在の5を前提に無条件で上書きしない。

## 5. 最終範囲と段階

最終対象は**11武器系統、現行の大型12種と幼体8種、登録済み20フィールド、装備・進行・狩りの循環**。新規デザインが並行して追加された種は、恒久IDの確定後に同じ能力・骨格契約へ登録する。存在しないIDを仮採用済みとして書かない。

最初は断岳剣・ガルドロス・風礫盆地の一連の狩りで基盤を確認する。次に既存7武器と各骨格、装備移行、不足4系統、各フィールドへ展開する。この最初の一本は検証のための区切りであり、「2G相当完成」の範囲を一武器・一体・一狩場へ縮める判断ではない。依存関係と完了条件は[05](05_implementation_acceptance_v1.md)を正本とする。

狩りの循環には、里での装備・持込品の準備、受注、支給と出発、探す・印を付ける、戦闘、回復・研磨、移動と追跡、討伐または捕獲、取得・帰還・生産を含む。制限時間・力尽き回数・終了条件は依頼データで持つ。既存の採集・納品依頼も、このフィールドと動作の品質対象にする。

## 6. 数値と根拠の約束

| ラベル | 意味 | 例 |
| --- | --- | --- |
| 原作資料で確認 | 機種・資料・ページ／映像時刻を示して確認した範囲 | PSP2Gの番号付き地図、MHFU説明書の装備部位・武器役割 |
| Kari現行 | 固定SHAのコード・JSONで読める値 | 走速6.4m/s、回避36tick、入力バッファ6tick |
| Kari初期仮値 | 本設計で試遊の開始点として選んだ独自値 | 技能+10/+15/+20、地形の高さ帯、射手防御比 |
| 要検証 | 原作または改修後の結果がまだ未確認 | 正確な無敵区間、日本版の全入力連係、改修後のiPhone操作感 |

原作の数値が未確認でも、状態遷移・保存・装飾枠などの機能実装は進める。細かな硬直、軌道、倍率を「完全再現」「2G実測値」と記録しない。動画内の40秒という位置は行動の長さではなく、WMVのフレームレートはsimulationの周期でもない。

調整は「姿勢と接地 → 判定 → 入力受付 → 間合いと後隙 → 威力と消費 → 難度」の順に行う。数値だけを遅くして重い動作と称さず、見た目だけを早くして判定時刻を残さない。2Gへどの程度近づいたかは、同じ開始状態からの連続比較と差分の記録で示す。

## 7. 読む順と仕様の優先

まず本書、[Claude開始指示](CLAUDE_START_HERE_v1.txt)、[05の受入条件](05_implementation_acceptance_v1.md)を読む。実装する領域に応じて01・02・03・04と、JSONの該当IDを参照する。02のモンスター章と03の装備章にまたがる異常・捕獲・報酬は、同じイベント契約を用いる。

`field_blueprints_v1.json` と `requirements_v1.json` は**設計用の機械可読ファイル**であり、現行ゲームのスキーマへ直接読み込ませる完成データではない。`bestiary:import` の入力にも使わない。Claudeが型・生成元・検証を整えてからruntimeデータへ変換する。

着手時にmainが進んでいた場合は、実装済みの差分を確認して残件だけを更新する。今回の採用方針を旧文書の「参考」に戻さず、衝突があれば利用者の最新指示と既存採用事項の対応を記録して解決する。
