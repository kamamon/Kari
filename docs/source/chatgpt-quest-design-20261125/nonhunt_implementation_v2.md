# 採集・採掘・納品クエストの実装監査

参照基点: Kari v0.22.0 / `4851d57ecc24c8fd127508b084999cec5d0e975f`。2026年11月25日。

この文書は、ユーザーの追加依頼に対する設計上の監査である。コード・公開データは変更していない。採集・採掘・現地納品・倉庫納品・貨物輸送が現在動作することを確認した文書ではない。

## 1. 現行実装でできること・足りないこと

| 対象 | 現在の状態 | 導入時に必要なこと |
| --- | --- | --- |
| 依頼の種類 | `QuestDef.kind` は `slay` / `hunt` のみ。`targetMonsterId`・`rankId`・`monsterSpawn` が必須 | 非狩猟の目的を明示する型。狩猟にだけ標的・戦闘ランクを要求する検証 |
| 地域 | 実行用フィールドは風礫盆地。登録簿の他の地名は制作計画 | 指定地域の完成前に受注可能にしない。盆地の地名だけ置換しない |
| 採集・採掘 | `FieldDef` に採取点・鉱床・採集の操作・採集袋がない | 採取点の定義、配置、状態、操作、入手結果、UIを追加 |
| 納品 | 野営地の座標はあるが、納品箱・素材の引渡し判定はない | 到達・相互作用・必要数・入手元の検証、成功判定 |
| 貨物 | 貨物の受取・保持・落下・回収・運搬はない | 通常所持品と分けた、runごとの貨物状態 |
| 所持品 | `SaveDoc.items` に道具と素材を保存する。持ち出しは `pouchOf()` が使用道具だけを選ぶ | 素材を既存道具欄へ押し込まず、今回取得分の採集袋を新設 |
| 達成・報酬 | 討伐・捕獲により成功し、帰還処理で戦利品を加算する | 非狩猟では納品完了だけで成功。納品済み必要量を報酬として戻さない |
| 里の納品 | 受注UIの全依頼が `startHunt()` へ進む | 出発せず、在庫確認と納品確認の画面で完結する別経路 |

出典: [型定義](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/data/schemas.ts)、[実行時検証・読み込み](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/data/validators.ts)、[シミュレーション](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/game/sim.ts)、[受注UI](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/ui/base.ts)。

### 仮のモンスターや空のtargetsで代用しない

現行validatorは標的の存在、フィールド内の巡回路、戦闘ランクを要求する。幼体用の `targets` は空配列を拒否する。さらに、シミュレーションの群れ達成判定は `targets.every(...)` のため、検証を外して空配列を入れると出発直後に成功し得る。採集依頼のためのダミー大型や、頭数0の標的を作らない。

目的と遭遇する敵を別にする。採集依頼に巡回する大型がいても、その大型の討伐・捕獲は依頼成功にしない。`rankId` が現在兼ねている「敵の倍率」と「進行順」を分け、危険回避の難度である星から敵能力を自動生成しない。既存24件は旧形式との互換を維持する。

## 2. 採集・採掘・現地収集納品

### 今回取得分の証明

今回のrunで採った素材を、`resourceId`・`count`・`sourceNodeId`・runの識別子と対応させて保持する。里の在庫、支給品、別のrunの未保存報酬は現地収集の必要数に算入しない。保管場所に同じ素材を100個持っていても、出発時の進捗は0から始める。

専用の採集袋と道具袋を区別する。現行の `carryMax` は回復液などの使用道具に対する上限で、素材用の既存上限ではない。新たな袋上限は設計値として追加し、各依頼の全必要量と予定余剰が入りきるかを検証する。上限到達時に採取点を消費してから品を捨てる処理は禁止する。

### 確定供給と採取点

必要品は確定入手とし、任意の追加品だけに抽選を使う。供給量は「対象点数×点あたり確定量×回数」で照合し、必要量と予備分以上を保証する。数だけでなく、実際に歩いて到達できる点だけを供給量に数える。

採取済み状態はエリアを出入りしても残す。途中で操作をやめた時や被弾した時は、報酬加算と残り回数減算の両方が未確定のまま戻るか、両方が一度だけ確定する仕様にする。タップ連打、同じ効果フレームの再評価、画面復帰で二重取得しない。

盆地の採取点は歩行可能な `shape` 内、岩や出口への進入を妨げない場所へ配置する。他の地域の地名・ルート説明は、位置が確定する前の設計案として扱う。大型の巡回を避けられる迂回路か待避場所が必要で、道具が無い・抽選が出ない・敵を倒さないと採取点へ行けない、という状態を作らない。

地形出典: [盆地](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/public/data/fields/basin.json)。

### 成功と精算

進捗表示は「採集 6/6・未納品」のように、持っている数と納品完了を分ける。全品が揃って納品箱へ到達し、「必要量をまとめて納品」を実行した時にだけ成功する。複数素材では一括納品を初期仕様とし、途中の一部納品に伴う返却・巻戻しを不要にする。

必要量を今回の採集袋から取り除き、余剰だけを帰還時の入手素材へ移す。現行 `closeHunt()` は `h.loot` 全体を報酬に合算するため、納品した必要量をそのまま `h.loot` に入れたままにしない。「納品で消費した数」と「持ち帰る数」の二重計上を禁止する。

現行の報酬validatorは `rewards.items` を素材IDに限定している。回復液などの道具を報酬にしたい場合は、そのままJSONを入れず、報酬の型と検証・保持上限を別途対応させる。新素材の用途は対応する加工・調合レシピが完成するまで設計案であり、説明文だけで実際に使用可能とはしない。

## 3. 倉庫納品の取引

倉庫納品は里で完結し、出発・狩猟タイマー・力尽き回数を使わない。無制限を表すために既存の `timeLimitTicks=0` を入れると現在のvalidatorに拒否されるため、時間を持たない目的型として表現する。

納品画面には、消費する素材名と数量、所持数、納品後の残数、得る報酬、一度限りであることを出す。受注・画面表示・会話既読だけで自動消費しない。

保存のトランザクション内で、最新の保存状態に対し次を一度に行う。

1. 未達成・未受領と受注資格を確認する。
2. 同じ素材IDをまとめた必要量と全在庫を照合し、不足なら変更しない。
3. 必要量を差し引く。
4. 報酬・達成記録・永久の受領記録を加える。
5. 保存完了後だけ、画面を「納品済み」に変える。

`settleRun.spent` は不足を厳密に拒否せず、残数を0以下なら削除する処理である。**倉庫納品の原価検証に `spent` をそのまま流用しない。** 工房の `checkCraft()` / `craft()` と同様に、表示時の確認と書き込み中の再確認を分ける。

`settledRuns` は最大300件で古いrunを削除する。一度限りの倉庫納品には永久の `claimId`、または削除しない当該quest IDの達成記録を使う。UIのボタン無効化だけに頼らず、書き込み内部でも繰返しを拒否する。報酬と原価の上限超過を黙って丸めて消費だけ成立させない。上限時の取引不可か、報酬の保留枠を明示して選ぶ。

出典: [所持品・納品に再利用できる純粋処理](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/save/profile.ts)、[書き込みと競合処理](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/save/saveManager.ts)、[IndexedDBトランザクション](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/save/saveDb.ts)。

## 4. 貸与貨物の輸送

貨物は倉庫アイテムや通常素材と別のrun専用オブジェクトにする。受取所で貸与された一個が、`未受取 → 運搬中 → 地面に置いた → 運搬中 → 納品済み` と遷移する。地面の貨物と手持ち貨物を同時に作らない。

被弾で落とす場合は壊さず、歩ける近くの安全地点に一個だけ置く。自発的に置く操作を用意し、回避・回復・戦闘へ戻れるようにする。エリア遷移時は運搬状態を維持し、到着地点の地形との整合を確認する。

地形外・岩内部・出口の向こうへ消えた時は、その貨物の既存個体を最後の安全地点か受取所へ戻す。新しい貨物を追加する復帰ではない。力尽き時は運搬を解除し、復帰地点を案内する。失敗・リタイア時に貸与物を所持品へ入れず、再受注時にだけ新しいrunの貨物を一個作る。

納品先へ持ち込んでも範囲に入っただけで勝手に完了させず、引渡し操作を要求する。通常攻撃の主ボタンとの競合を避け、iPhoneでも「拾う／置く／渡す」が今の状態に一致して読めるようにする。護衛NPCや破損耐久はこの輸送と別機能として扱う。

## 5. 失敗・時間・保存の境界

**「出発前の所有物を失わない」は、採集素材や納品用の在庫を勝手に差し引かない、という意味に限定する。** 現行では、失敗・リタイアでも実際に使った自前の回復液・研磨石などは差し引く。支給品が先に使われ、未使用の持ち込み道具は減らない。この動作を非狩猟でも維持するなら、依頼仕様に明記する。

現行の結果保存失敗は、アプリのメモリ内の未保存配列へ残し再試行する。ページを閉じても未保存の採集袋・貨物・取引が完全復元される実装ではない。再開機能を約束する場合は、専用の永続チェックポイントと原価・報酬の一回処理を別途実装する。

現行の制限は60Hzで `timeLimitTicks × field.timeLimitScale`、盆地は倍率2。非狩猟も最終表示時間を正本にし、v1の明示フィールド時間方式へ合わせる。倉庫納品は別経路なのでこの時計を使わない。収集終了で時計を止めず、納品完了まで帰路を含める。

現行は同じtickに重なると討伐→捕獲→リタイア→力尽き→時間切れの順で結果を確定する。非狩猟の「納品操作が成立する最後のtick」の扱いを明示し、納品と失敗の両方が処理されないよう一つの結果遷移にまとめる。完了後に追加採取する時間は設けず、必要なら帰還演出だけを行う。

出典: [時間計算](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/game/field.ts)、[実際に使った自前道具と結果確定](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/game/sim.ts)、[保存呼出し・未保存再試行](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/app.ts)。

## 6. 経済・進行・制作順

現在、商店の買い取り値は `shop.sell` に列挙された素材だけにある。新しい天然素材は、登録しただけでは売却できない。新しい納品報酬の値は、採取・移動・納品にかかる時間、余剰素材の売値、道具消耗をまとめて確認する。一度限りの倉庫納品は自由周回の資金源として計算しない。

天然鉱石とガルドロスの身体素材を別IDにし、採掘によって既存の戦闘段階や希少な身体素材を迂回取得させない。将来の武器防具案が天然資源を要求する時は、`obtainableMaterials()`・`materialRanks()` に採集点由来の経路を追加する。現状では素材の取得可能性がクエスト報酬と標的の戦利品からだけ計算される。

既存の `requires` は全件ANDで、前提依頼のランクも検証する。非狩猟では地域公開と任意依頼の進行を明示し、初級の安全な採集を終盤依頼の無意味なランク条件で塞がない。今回の追加36件は既存の物語14件の必須条件へ後付けしない。

制作は、(1)盆地の敵なし採集1件と採掘1件、(2)現地混合納品、(3)里の一回納品、(4)貸与貨物の輸送、(5)他地域へ拡張、の順を推奨する。各段階で目的・所持品・保存の経路が成立した範囲だけを受注可能にする。

出典: [商店価格](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/public/data/shop.json)、[取得経路・ランク検証](https://github.com/kamamon/Kari/blob/4851d57ecc24c8fd127508b084999cec5d0e975f/src/data/validators.ts)。

## 7. 実装時に確認すべき受け入れ条件

- 必要品を全て持っていても未納品なら成功しない。偶発的なモンスター討伐・捕獲でも成功しない。
- 必要品は抽選・再出現待ちなしで確保できる。最短経路でなくても目標時間・制限時間に収まる。
- エリア往復・連打・被弾・一時停止を挟んでも採取点から二重取得しない。
- 袋の上限を満たす直前・直後でも、必要品を失わず達成可能。
- 成功時に必要量だけ消費し、余剰だけ持ち帰る。失敗時は今回取得分を失うが、既存在庫は保持する。使った自前の道具だけは現行どおり差し引く。
- 倉庫納品で、所持不足・別タブの売却・連打・保存失敗が起きても、原価だけ消える／報酬だけ増える状態にならない。
- 倉庫納品の一回資格は、300回以上の別の狩猟を終えても復活しない。
- 貨物の落下・力尽き・エリア移動・安全地点への復帰で複製や消失が起きず、破壊された扱いで詰まらない。
- 旧セーブの狩猟達成回数・所持品・装備を維持し、新しい保存構造にのみ必要な移行を行う。
- iPhoneで素材の名称・必要数・所持数・未納品状態・目的地・確認操作が読める。

以上は今後のゲーム実装の検査項目である。この監査ではソースを読み、該当箇所を特定した。ゲームの自動テスト、実機試遊、新機能の動作確認は実施していない。

## 本提出の確定方針

共通仕様はnonhunt_system_v2.md、各原稿・必要数はnonhunt_catalog_v2.jsonを正本とする。32件の現地依頼には回復液3・研磨石1を明記し、4件の拠点納品は支給なし。拠点納品は保護残数と報酬容量を保存直前に確認し、不足・上限時は消費前に全取引を拒否する。報酬は通貨と納品後の余剰素材だけで、使用道具をrewards.itemsへ足さない。

貨物の2回輸送は往路2回＋途中の復路1回で、最終箱を渡した時点で達成する。古い貨物個体を無効化してから同じ貨物IDを受取所へ戻す。期限到達・3回目の力尽きと同じtickの納品は成立させない。ページ終了後の途中再開はこの初期版に含めない。
