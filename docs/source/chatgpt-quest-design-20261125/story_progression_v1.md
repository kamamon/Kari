# 本筋14依頼の難度・時間・解禁設計メモ

作成：2026年11月25日（日本時間）。main `9a5443ab1ac813512deac03422ee996f57f8a900`（v0.21.0）と、ストーリー案PR #7を参照した採用前の提案。

## 主線の役割

物語案「帰り道の灯」のST01〜ST14、標的、順序、7狩場、14の仮題を維持する。ST01・ST02は既存の `quest.basin.003` と `quest.selvark.r1`。残り12本は `quest.story.st03`〜`quest.story.st14` という新規ID案にする。物語の同種を既に狩っていても、旧盆地版の自由依頼を後半地域の新事件の成功として扱わない。

ST13のグラセドンは登録簿の**上級 rank.3**、ST14のセオルミドは**極級 rank.4**である。セオルミドの恒久IDは表示名に似ていない `monster.segranio` を保持する。グラセドンを極級に変更したり、序盤ガルドロスと同じ個体が急成長した扱いにしたりしない。

★は受注時の難しさを伝える表示値。`rankId`の代用にしない。ST05〜12は登録簿の初級原種を、当該物語事件に出る中級・上級個体として調整する提案である。元の初級自由依頼を難しくする意味ではなく、種登録の初出rankも変更しない。既存の全体ランク倍率を変更せず、対象の基礎値がどの段階を表すかを明記して二重補正を避ける。

星は単調なレベル番号ではないため、すべての星を主線で通ることを必須にしない。★1は幼体・練習系の自由依頼、★7は通常の極級自由依頼に持たせ、終盤に準備の選択肢として案内する。本筋ST14は多方向の読み分けと時間差攻撃の理解をまとめる★8案。ST13の★6からの上昇が大きすぎる場合は、初回ST14の攻撃組合せ・隙・体力を調整し、測定後に★7へ下げる選択肢を残す。調整のために本筋を15本へ増やしたり、★7の周回を必須にしたりしない。

単体の制限時間は実際の出発後カウントであり、`timeLimitScale=2`をさらに掛ける前の入力値ではない。各時間は初期目標で、実測値・保証値ではない。

## 主線の解禁

1. ST01とST02は、既存自由依頼の受注条件をそのまま維持する。画面でST01→ST02をおすすめしても、ST02を先に狩れる。片方の既達成を無効にしない。
2. ST03の条件はST01とST02の両方の成功記録。S0では章の報告だけ先に読め、未実装の湿原へ出発はできない。
3. ST04以降は前のST依頼成功を条件とする。通常の狩猟以外の会話・痕跡・設備操作を必須化しない。
4. 全段階で、プレイヤーの達成条件と収録内容の準備条件を別に確認する。登録済みでも、対象の戦闘と指定狩場が未実装なら受注不可。
5. 既存ガルドロスの4段階連鎖、他大型11件、幼体9件を主線既読や新許可で再ロックしない。

この案の `prerequisites` は設計資料の項目。現行 `requires` と同じ全件ANDで表せるのは、上記の単純な依頼成功の部分だけである。章の準備状態・会話・設備は架空のクエストIDとして `questClears` に混ぜない。

## 自由依頼で昇級したい人の「選択キー」案

本筋を進めなくても、新規の自由依頼の上位帯へ行ける代替ルートを設ける。対象は**今後追加する自由依頼**であり、現在開放済みの24依頼の受注条件へ後付けしない。本筋側にもこのキー条件を重ねない。

| 中級の新規自由依頼 | ST04達成 | 初級キー5件から異なる2件＋既存中級ガルドロス `quest.basin.r2.001` 達成 |
| 上級の新規自由依頼 | ST08達成 | 中級キー5件から異なる2件＋既存上級ガルドロス `quest.basin.r3.001` 達成 |

### 仕組み上の注意

- 「5件から2件」は**異なる依頼IDの達成**を数える。同じ依頼を2回周回しても1件。
- 開放条件は「本筋達成 **OR**（選択キー2件 **AND** 審査依頼達成）」である。現行の `requires: string[]` は全件ANDだけなので、新しい条件型と表示・検証が必要。OR候補を平坦な `requires` に並べて全件必須にしてはいけない。
- キー候補が不足している未収録段階で、この代替ルートを有効にしない。少なくとも2件が実装済みであり、それぞれが当該許可なしで受注できることを検査する。公開目安は選択を保つため3候補以上。
- キーの画面は「2/2達成」「どちらか達成で受注可能」を明示する。未達の別ルートを同時に要求しているように見せない。
- 初期版ではキーのおすすめ表示だけを導入できる。許可による出発制御は、保存・OR・重複排除・循環検出を実装してから有効にする。
- 既に受注済み・開放済みの記録は移行で保持する。通常の実績や所持品を減らさない。失敗・リタイアは達成数に加算しない。

## 主線の所要時間目標

14狩猟の出発から目標達成までの設計値を合計すると**169〜234分（約2時間49分〜3時間54分）**。これは移動・探索を含む各クエストのクリア目標時間の合計で、戦闘だけの正味時間ではない。

里での会話・装備検討・購入などに約45〜75分を見込むと、失敗・周回のない主線直進は仮に**214〜309分（約3時間34分〜5時間9分）**。任意の素材集め・自由依頼・再挑戦を含めた体験は人によるため、プレイ時間保証や製品のボリューム表記には使わない。実際の狩猟時間を測り、まず約4〜6時間で主線が一周できるかを確認する制作目標とする。

主線の長さを増やすためだけの同一個体の連続周回や、稀素材待ちを課さない。装備の目安は案内し、全武器で通れるかを試す。とくにST13→ST14では最適装備を持つ熟練者だけの計測で合格にせず、通常進行の装備と初見の失敗理由を調べる。

## ネタバレと受注画面

- 依頼一覧に出すのは、開放済みの依頼と次の物語目的まで。未遭遇の希少種名・最終依頼名・全14本の結末を最初から一覧に並べない。
- 先の章は「次の調査先は、現在の報告後に判明」と表示。★や時間だけで未収録依頼を出発可能にしない。
- 受注直前には依頼人、目的、狩場、★、制限時間、失敗条件、支給品、報酬、短い予告ヒントを同じ画面で確認できる。
- `storyOutcome` は制作側と帰還後の記録用。出発前の依頼カードにそのまま出さない。
- 職人ロクハ、運び手イサネ、見回り役セナキはPR #7の仮名。正式採用前は依頼人を役割名で表示できる。
- 長い会話は安全な里か成功後に読む。省略しても進行や報酬は変えず、記録から再読できる。

## 照合と留保

- 14行、ST01〜ST14の重複なし。新規ID12件・既存ID2件。種ID・表示名・狩場をv0.21登録簿と照合した。
- 全依頼文は120〜200字内。目標最大時間はすべて制限時間未満。依頼前提に後の依頼や自分自身は含まれない。
- ST13は上級、ST14は極級を維持。捕獲可否が未実装の2種は、JSONに条件と必要作業を明記した。
- 確認していないのは、星評価の実機妥当性、初見クリア率、武器間の所要時間差、未実装の6狩場・2種の狩猟、上位物語個体の素材・報酬バランス、会話・保存・解禁のゲーム内動作。
- 読み取り元：`public/data/bestiary.json`、既存クエスト3JSON、`public/data/ranks.json`、PR #7の `story_design_v1.md` と `implementation_handoff_v1.md`。この作業ではゲーム本体を変更していない。


## 統合時に補った装備経路

ST02の本文を順不同受注でも成立する文に修正し、clientは現行差分と同じ「穀物の運び手」に統一した。仮の固有名は内部候補として保持し、公開用依頼人は役割名を使用する。
