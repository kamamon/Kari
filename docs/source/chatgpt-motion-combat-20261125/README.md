## 2. 具体的に差し替えた部分

### 身体と動作

- 全7系統の通常歩行へ接地処理を接続する。要求された入力速度ではなく、実際の移動量から足運びを進める。
- 直進・緩い旋回では支持している足を世界座標に保つ。停止時は浮いた足を下ろし、その場の大きな旋回は踏み替える。走りには短い空中局面を持たせる。
- 急反転では脚が届かなくなる前に80msで固定を解除する。急旋回中の完全な無滑走は保証しない。
- 断岳剣の縦斬り・横薙ぎ・抜刀斬りを、脚の接地IKと骨盤の回転・上下・前後移動で支える。横薙ぎは、背と胸だけの強いひねりを骨盤へ分散する。
- 現行の硬い靴の寸法に合わせて足底を補正し、踵を上げたときにつま先が床へ沈む問題を直す。
- IKを解いたあとに骨だけを再補間する経路を外す。命中窓と弓の発射tickでは遷移を終え、武器軌道へ一致させる。
- ヒットストップの最後のstepまで、処理済みの接触時刻を表示する。溜め保持の時刻は維持する。
- 検査用 `solveState()` の歩行位相を絶対時刻から求め、異なる時刻が実際に異なる脚の状態を検査するようにする。

断岳剣の既存武器軌道と攻撃の時刻・root移動曲線は維持する。他6系統の攻撃キーを全面的に作り直す作業は今回の適用差分に含めず、各武器の支持足・荷重・予備動作・制動・連携の案を設計書へ示した。

### モーションごとの攻撃力

主連携の後半と、狭い打点・長い溜め・長い拘束を伴う技へ報酬を寄せる。MVは係数×100で、画面に出るダメージではない。全33攻撃の値はJSON/CSVと設計書の一覧を正本とする。

| 武器 | 代表的な提案MV |
| --- | --- |
| 断岳剣 | 横薙ぎ70、縦105、溜め157.5 / 220.5 / 294、抜刀100 |
| 護刃 | 主連携24 → 30 → 56、盾28、踏み込み48 |
| 長尖槍 | 主連携36 → 42 → 72、上段38、構え30、受け返し155、踏み込み82 |
| 大槌 | 叩きつけ60 → 横殴り76、溜め基礎72 / 段階122.4 / 183.6 / 273.6、抜刀76 |
| 双剣 | 主連携18 → 22 → 30+30、二段突き20+30、連ね16+18+20+42+42、抜刀27+27 |
| 太刀 | 主連携38 → 44 → 72、下がり32、兜割り142、抜刀56 |
| 環弓 | 射撃22 / 58 / 112 / 185、散らし17×3 |

大槌の主2段は循環するため「後半」であり、固定された終端ではない。連携専用の既存行動IDの威力を調整しており、どの技にも自動で付く「最後の一撃ボーナス」は追加していない。受け返しは防御成功条件を維持する。

武器本体の攻撃力、敵HP、実際のヒット窓・発射・派生・キャンセル時刻、移動量、スタミナ規則は維持した。弓の発射時刻と双剣二段突きの最終判定がactive区間から外れる分類だけを修正した。溜め倍率は刃消耗へ掛からない既存仕様のため、溜めのダメージ/刃効率が上がる点も分析へ含めた。

## 3. 取り込み方法（Claude向け）

最新v0.21用は `implementation/current-main/`。元の統合パッチと個別パッチはv0.20監査の再現用として保持する。重ねて適用しない。下は最新用の例で、この納品があるリポジトリのルートから始める。

```sh
git worktree add ../Kari-motion-review --detach 9a5443ab1ac813512deac03422ee996f57f8a900
python3 chatgpt-inbox/motion-combat-20261125/implementation/current-main/apply-proposal.py --repo ../Kari-motion-review
python3 chatgpt-inbox/motion-combat-20261125/implementation/current-main/apply-proposal.py --repo ../Kari-motion-review --apply
cd ../Kari-motion-review
npm ci
node --experimental-strip-types --no-warnings tools/gen-weapons.mjs --strict
npm run check
```

`--apply` のない実行は読み取りだけ。対象21ファイルの入力ハッシュが合わなければ止まり、別の変更を勝手に上書きしない。基点以降に変更がある場合は、差分を読み、競合する行動IDや骨格処理を移植する。生成JSONだけを編集すると、次の生成で消えるため、必ず生成元も取り込む。

逆方向の確認は `--reverse`、戻す実行は `--reverse --apply`。逆適用も変更後の全ハッシュが一致する場合に限る。このスクリプトはコミット・push・merge・公開を行わない。

比較スクリプト `implementation/balance/measure_balance.mjs` は、元の実装と提案データを比較する。**本体へ適用する前の基点＋inbox**で実行する。適用後のデータを「旧版」として誤って比較しないよう、元のファイルのハッシュを検査する。

制御DPSは、初期武器で全判定枠が命中し、部位係数1・鋭い刃固定という条件。実際の入力派生、時間、命中停止、溜め、勢い、スタミナは通すが、敵AI・幾何的な空振り・矢の飛行時間・刃の経時消耗は除く。討伐時間や人の命中率の実測として扱わない。

## 6. 確かめていないこと・Claudeへの引き継ぎ

この実行環境ではWebGLを起動できず、通常速度のゲーム映像・iPhone実機・実際の入力感の検収は行えていない。掲載画像は実際の骨行列とスキニング後の頂点をCPUで描いた形状図で、ブラウザの描画結果ではない。

取り込み後は、通常速度と0.25倍の正面・側面・後面から、歩行→停止、90°/180°反転、攻撃開始、命中停止、溜め解除、弓発射を確認する。特に急旋回中の足の滑り、壁で攻撃のroot移動が止まる場合、斜面・段差、すべての防具の貫通は残る確認範囲である。

掌の向き・指の把持、新しいGLB、他6系統の全攻撃クリップ、回避・被弾・起き上がり・道具の正式クリップは制作対象として残る。GLB化では、17骨のワールド姿勢を新しい親座標へ移す `rigVersion: 2` のadapter、武器socket、靴底輪郭、toe骨、動くメッシュのboundsを一緒に統合する。

難易度は、全大型・幼体・群れ・強化段階について、技の開始数→後半到達数→実命中数、行動中の被弾、スタミナ・刃、怯み・部位破壊、討伐時間を実機で測る。弓は散らしの実命中本数と回復待ち、大槌は溜め強化による拘束連鎖を優先する。これは今回の数値を最終化するための確認であり、既に完了したものとして扱わない。
