## 0. 依頼の結論と完成条件

利用者の指摘「フィールドのエリアの外が見えて何もない草原が見えて萎える。2Gのフィールドのように自然の何あるフィールドとなるように改善して」を解消する。現行の起伏を作るだけの実装を、実在する地形の成り立ち・生態・見通しを考えた景観へ仕上げる。原作2Gの画像・地形・モデル・音源・固有名・データを流用しない。参考にするのは地形の奥行き、エリアの個性、自然な境界、戦闘の視認性である。

最終形: 通常視点、上向き、見下ろし、登攀後の高所、境界際、各出口の全方向から、何も置かれていない外側の平坦な草地、模型の端、浮く岩・木、黒い穴、地面と空の不自然な継ぎ目が見えない。海・雪原など自然に開けた眺望は許容し、意味のある地平線・地質・水系を描く。霧で一律に隠すことは不可。狩猟・回避・弓照準・登攀・採取が従来どおり成立し、狩場ごとの違いをスクリーンショットで識別できること。

## 3. P1: 外周地形を自然な形に再設計

### 3.1 描画レイヤーと距離
距離dはプレイ範囲の外周から水平に測る（現在の座標、m）。数値はKari用の初期設計案で、原作から計測した値ではない。既存の視点、relief、地形の寸法に合わせて調整する。
| レイヤー | 距離の目安 | 役割 | 表現 |
|---|---:|---|---|
| playable | d≤0 | 戦闘と移動 | 現行の支持面・岩・段差と一致 |
| edge | 0〜12m | 境界を地形に見せる | 岩の根元、地層、根、崖下、藪、岸 |
| near | 12〜40m | 遮蔽物と地形の奥行き | 岩群、樹林、尾根、谷、屈曲道 |
| mid | 40〜130m | 生態と地域の奥行き | 対岸、森の斜面、谷筋、海面 |
| far | 130m以遠 | 地平線を形成 | 遠方稜線、樹林シルエット、海の地平線、空 |

### 3.2 メッシュと接地
- buildLandscapeSurfaceの共有頂点を活用し、近景と外景の重なり/隙間をゼロにする。現行の三角形は頂点の距離から内外を決めている。凹形状では頂点だけでなく三角形の辺と外周の交差、中心点も確認する。必要ならpolygon clippingまたは境界周辺の細分化を行う。
- 内側の高さはreliefAt、支持面はworldと同じ正本。段差の穴・池・登攀帯・乗越え帯を保つ。外側だけの高さ場はplayableから独立し、境界近傍を既存の崖と滑らかにつなぐ。遠方に広い一枚の平面を戻さない。
- 立体の斜面を「全周ほぼ同じ高さの円環」にしない。方角ごとに地質と標高の制御点を置き、広い原には低い見晴らしと下降する谷、狭路には側壁、巣には岩盤の奥行きを作る。高度だけでなく地層方向、浸食溝、尾根と谷の関係を表す。
- cliffの背面から外景に接続する面の高さと法線・UV・色を照合。崖の根元に岩片や土砂、植生をつなげる。影・接地・色で切れ目を抑える。外側の岩/樹木は最終形状全体で外周から離れること（中心点の距離だけで判定しない）。
- 海岸は海へ下る地形と連続水面。海側には低い水平線を作り、全方位を同じ山で囲まない。湿地の水は窪みごとに岸を成形する。水面の三角形は水位の交線で切り、岸から飛び出す四角い水を作らない。池の中の釣り場と外景水面を混同しない。
- 鉱山/洞庭/樹洞は空が見える場所を設計で限定。坑内扱いの箇所のみ局所的な天井・アーチ・洞口を置き、歩ける範囲、モンスターの上方の攻撃、弓照準を遮らない。完全な洞窟の当たりを実装する場合は別PR。

### 3.3 出口と地域連続性
現行はgateの外向きと乱数で曲がる道を作るが、接続先の個性を考慮していない。各接続に一対の視覚アンカーを設定する。
- 各出口に `fromAreaId/toAreaId`、入口から見た方位、`anchorKey`、地質・植生、道の幅、曲がり方向、眺望の種類を持たせる。対になる出口のanchorKey、地層・草・岩の色を合わせる。
- 実際のarea.boundsは互いに大きく離れた独立区画なので、世界座標を結ぶ直線が本来の地理だと仮定しない。接続グラフと既存の地図方位を使う。地図のD-133（+Xが地図の西）に注意。
- 視覚用の小道は現行出口の到達判定と一致。出口の左右5m程度を開き、出口から約18〜30m先で自然な屈曲・岩棚・樹林へ隠れる。道の外側を不均一な縁・砂利・轍・草の斑でつなぐ。直線的な矩形のテクスチャ帯を残さない。
- 門柱は必要な視認性を保ちつつ、自然な岩・根・海食洞の切れ目に調和させる。プレイヤーが出口を見つけられることをテスト。既存exit.rと移動条件は変更禁止。

| 資産群 | 最低限の新規/改修バリエーション | 実装方針 |
|---|---:|---|
| 広葉樹 | 6形（若木、老木、傾木、枝分かれなど） | 幹・根・枝・不均一な葉群、樹皮と葉の画像材質 |
| 針葉樹 | 4形 | 枝の段と先細り。樹冠の球の縦積みを避ける |

| 植物 | シダ、低木、枯れ草、葦、雪地草を各3形 | atlas、alphaTestの切抜きと交差面 |

- 既存 public/assets/textures/env/ と materials/ の画像を優先。materialImages.tsのキャッシュとUV管理を利用。新規画像の制作時はart-source/に原本、publicにWebP等の実行画像、docs/asset-manifest.jsonにID/出所/状態を登録。原作スクリーンショットを貼り付けない。
- 近景は枝の先から見ても自然なシルエット。中景では低ポリ/葉群板、遠景は樹林帯の簡略化を用いる。樹木を等間隔・同一サイズ・同じ色に並べない。生態上の群落と空地、日当たり/湿り、傾斜に応じる。岩は地層の向きと高さを合わせ、空中に浮かないよう根元を埋める。
- テクスチャの長い直線・繰り返しの格子・急な色の切替を避ける。頂点色やsplat maskで草/土/岩を混ぜ、道に路肩を作る。アルファの草木は透明ソートを減らすためcutout中心。霧は空の色に連続、近距離のモンスター予兆や採取表示を消さない。蒸気、雨、胞子は少量の描画専用演出とする。

## 5. P3: 実行データ構造とコード変更箇所

### 5.1 推奨データ構造（新規の描画専用データ）
実行例: public/data/field_landscape_v2.json。content indexに登録し、src/data/validators.tsでschemaVersion、field/area/exit ID、有限値、範囲、素材ID、相互接続を検査する。既存のfieldLandscape.tsのProfileSeedは読み込み時の既定値として残し、未知のfield/areaを警告する。旧データ互換を考慮し、最終的な20地域完成時は未定義を検査エラーとする。
```json
{
 "schemaVersion": 1,
 "fieldId": "field.basin",
 "areaId": "a4",
 "style": "meadow",
 "seedPolicy": "fieldId:areaId:landscapeVersion",
 "sectors": [
   {"sectorId":"ridge","azimuthDeg":[0,90],"edge":"strata_cliff","mid":"wooded_ridge","elevationBandM":[6,30]},
```

### 5.3 処理手順
```text
load validated world + visual profile
 -> derive visible area's outline and reciprocal exits
 -> lock playable surface + collision-related coordinates
 -> author sector-based outer terrain / water / cliffs
 -> build seamless topology, evaluate contact and exit corridor
 -> place seeded ecological clusters + art variants
 -> merge/batch + choose LOD + build distant silhouettes
 -> show active area; prebuild only within measured budget
 -> render sky/fog/shadows and report diagnostics
```
描画乱数は戦闘の乱数と独立させ、同じfield/area/version/seedで再現する。フレームごとに全景観を再生成しない。隣接先読みやLOD切替によって採取・敵AI・戦闘seed・保存を変更しない。

## 6. P4: モバイル描画最適化

既存目標（狩場100 draw calls、200,000 triangles）は維持。代表画面だけでなく大型戦・群れ・最高視点・草が多い原でも計測する。目標を130に変更したのは里だけで、狩場へ適用しない。
- 草・岩・樹木・同一材質の景観はInstancedMesh/mergeでまとめる。樹冠の形状バリエーションはatlasとLODのバッチで管理。大きな近景の根/幹/枝と中遠景の形を分ける。
- LOD目安: 画面高60px以上=近景、18〜60px=中景、18px未満=遠景。距離だけでなく画面上の大きさを考える。切替にヒステリシスを持たせる。遠景は影を落とさない。草の風は既存WIND等の共有uniformを使う。
- prebuildAreas()は描画の待ち時間とメモリを計測し、必要なら現在＋隣接2〜3エリアの予算/遅延読込/LRUを実装。非表示エリアのGPU資源を増やし続けない。共有textureのキャッシュと所有権を分離し、古いscene破棄で他画面の材質を壊さない。
- 画像は近景用512〜1024pxを標準の開始値とし、特に大きな資産だけ2048pxを検討。atlas、mipmap、圧縮、必要に応じ解像度設定を採用する。外景が読み込めない場合も、旧平坦草原に戻さず形状と色のフォールバックを描く。
- 実機目標はiPhone/iPadの設定を明記し、通常狩猟で30fpsを安定目標、可能な端末で60fps。これらは新規提案で実測値ではない。frame timeの中央値/p95、area切替時間、ロード、10往復後のメモリ/texture数を改修前後で記録。設定変更で戦闘のtickが変化しないこと。

## 7. 受入れ検査（必須）

別添 acceptance_checklist.json を使用する。既存790件(#43時点)・基準コミット履歴802件に固定せず、最新mainの全テストを維持し、新しいテストを足す。テストの失敗を件数の変更や上限の緩和だけで解消しない。
1. 全20地域の全実在エリアを列挙し、同じ入力で同じ地形、ID重複/欠落なし、座標有限、法線/UV/インデックス正常を確認。内側の接地高さ誤差は既存基準に合わせ、頂点で1mm以内を目標。内部三角形の中央・交差辺も調べる。外景のモデル/水の接触は形状単位で検査。採取・登攀・出口・敵ルートは保存。
2. 全エリアの中央・各出口手前・高所・最も見通しが開く境界際から8方位、pitch -0.25/0.30/1.15（既存の範囲）を撮影。まず全域の簡略レンダー/ID maskで欠落・空洞・均質な外平面を検出し、失敗箇所は本番WebGL画像で追跡。正規の低い視点と高所視点は全地域の各種エリアで実写を保存。
3. 入口の先を向いた画面、同じ接続の相手側を並べ、地層/植生/ランドマークの連続性をレビュー。出口に向かう入力だけで移動できること。海と洞の開け方も確認。
4. 景観だけのテスト成功では「2G相当の品質」と判定しない。画像を実際に目視して、境界露出、地形の奥行き、自然なシルエット、地質と植生、戦闘の視認を各0〜2点で採点。各項目1以上、計8/10以上、平坦な外草原・穴・浮遊・出口遮断は1件でも不合格（新規のレビュー基準）。文字化けや画像読込エラーも別記。
5. 基本コマンド: npm ci; npm run typecheck; npm run test; npm run build; npm run smoke; node tools/landscape-shots.mjs。ツール実行にChromeが必要な場合は既存設定を使う。ブラウザ検査の全体、採集遠征、通常狩猟、群れ、旧arena、里を確認。失敗時に描画上限を上げて合格扱いにしない。
6. iPhone/iPad実機はCIのヘッドレス描画と別枠。実機未実施なら未検証と記録する。画面比較と計測値をPRに添付。main統合後、GitHub Pagesで新しいビルドSHA・公開状態と実際の表示を確認する。
