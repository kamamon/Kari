## 4. Claudeへの修正提案と取込の手順

### 先に、`fields` が失われる箇所を直す

テンプレートには `fields` があるが、現行の `src/data/bestiary.ts` の `mergeBestiary` は `species` と `frames` だけを処理し、`tools/bestiary-import.mjs` の書き出しにも `fields` がない。検査は通るのに狩場の説明が消える。

最小の修正案は次のとおり。

1. `BestiaryDef` に任意の `fields`（各項目は `name`、`terrain`、任意の `mood`）を追加。
2. 名前をキーに既存の狩場を保持・更新。同じ入力内の重複、空の名前/地形、不正な配列を拒否。
3. 種・狩場のいずれかが不正なら取込全体を中止。既存の番号・実装状態・原画を守る動作を維持。
4. CLIの出力JSONにも `fields` を保存。狩場の案と、実際に歩ける `public/data/fields/` の定義は分ける。
5. 「狩場が残る」「再取込で更新」「不正な入力で全体を戻す」「CLIで書いて読んでも残る」を検証する。

### その後、A→B→C→Dを正式に取り込む

取込はClaude担当。原本4JSONと例外を確認してから、既存の `bestiary:import` をA→Dの順で実行する。
取込後の期待値は初級成体13＋幼体8、中級20、上級25、極級20、計86。状態はimplemented=1、art=12、planned=73。
`tests/bestiary.test.ts` と `tools/smoke.mjs` にある「13件」「上級0件」「生態はまだ」の期待値も、この件数と生態8項目の表示へ更新する。
既存13種を抽出して固定ID・番号・原画が保たれたことを確認し、`typecheck`・`test`・`build`・`assets:validate` とブラウザ検査を実行する。
受領後、掲示板と引き継ぎ、必要なら制作計画書PDFの一覧も更新する。

### 実装へ進めるときの具体案

- **技**：`moves` の矢印前を見える予備動作、後を攻撃として、採用した1種から既存の `startup / active / recovery / hitWindow` 形式へ落とす。範囲と向きが確定する時点を置き、避けられる空間を残す。図鑑の短句だけから秒数や当たり判定を自動確定しない。
- **部位と素材**：`organ`・`parts`・`materials`・`armorLook` を同じ器官に結び付ける。破壊後に使えなくなる技や短くなる範囲を決めると、見た目と戦術、報酬がつながる。
- **同時出現**：`pairs` の重複を順不同のID組としてまとめ、同じ `habitat` と初登場段階を確認して依頼候補にする。遭遇理由をエリア内の餌場・水場・移動路に配置する。2体AIや同時ヒットの仕組みは別途実装する。
- **幼体**：`baseId` の骨格を利用しつつ、薄い殻・短い膜・小さい器官を形として変える。単純縮小だけで済ませず、`pack` を群れ数の範囲として使う。
- **制作順**：既存12種の原画の採用判断と、2体目の大型の選択を先に行う。今回の65種を一度にモデル化せず、採用した種について設定図→モデル→予備動作→判定→実機確認を1体ずつ進める。
