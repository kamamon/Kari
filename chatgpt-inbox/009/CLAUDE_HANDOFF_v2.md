### 各骨格の代表1種から、同骨格の次種へ進む受入順

1. **形と描画の入口**：`src/render/monsterRig.ts` の `MonsterRig` に合わせる。現在の `src/render/view.ts` は `rigFamily === 'quadruped_heavy'` なら `GaldrosRig`、それ以外は `DummyRig` の二択。種または骨格の生成処理へ拡張し、全種がガルドロスか訓練人形になる状態を解消する。四足重獣の共有は、同じ外形の使い回しとは分ける。
2. **部位・技・動き**：`src/data/schemas.ts` の `MonsterDef`、既存 `public/data/monsters/galdros.json`、`actions/galdros*.json`、`tracks/galdros*.json` を参照し、対象の `monsters/`・`actions/`・`tracks/` を作る。`public/data/content.json.files` へ登録する。`createMonster()`・`stepMonster()`・`monsterShapes()`（`src/game/monster.ts`）で、技の予告・攻撃・後隙、部位破壊、表示と当たりの一致を確認する。
3. **属性と状態異常**：決定済み方針は `docs/elements.md`。現行の登録簿に属性名があっても、ゲームの攻撃効果を実装したことにはならない。各種の必要分を実装するか、未実装効果を明記する。紙面の技をすべて実装済みとは表示しない。
4. **狩場と一巡**：`public/data/quests.json` の `targetMonsterId`、`public/data/fields/*.json` の `routes[monsterId]` を結ぶ。`src/game/sim.ts` の生成、`src/game/roam.ts` の `createRoam()`・`nextHop()` を使い、発見・巡回・巣・休息まで通す。新狩場は登録簿 `fields[].fieldId` と名前を合わせる。
5. **報酬と保存**：素材を `public/data/items.json`、報酬を `loot.json` と依頼へ登録する。討伐・必要な種の捕獲・帰還後の `App.settleRewards()`（`src/app.ts`）から保存まで確認し、素材が別種の名前やIDのままになっていないか見る。登録簿の `state: implemented` はこの受入後に更新する。
6. **次種へ展開**：`assembleContent()`・`crossCheck()`・`validateBestiary()` の相互参照検査を通し、描画・部位・技・終了・報酬まで通った代表を同骨格へ展開する。現行Simは依頼1件から標的1体を生成する。複数種を順に実装する作業に、同時複数体・幼体群れ・超大型戦を混ぜて完了扱いにしない。

Claudeが実装後に使う既存コマンド：Node.js 22以上で `npm ci`、`npm run bestiary:import -- --check`、`npm run check`、`npm run smoke`。登録内容を変えたら `npm run design:doc` も更新対象。ここに列挙したコマンドを、このレビューで実行したという意味ではない。
