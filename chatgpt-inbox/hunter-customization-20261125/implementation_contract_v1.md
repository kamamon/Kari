# ハンター外見変更 実装契約 v1

霧境の狩人 — VEILBOUND HUNTERS / Kari
確認日: 2026-11-25（日本時間）
確認基点: `main` / `4851d57ecc24c8fd127508b084999cec5d0e975f` / v0.22.0
状態: **Claude向けの実装提案。キャラメイク・保存移行・モデル差し替えは未実装。**

追加依頼に従い、女性・男性・中性的な外見、肌色、髪型、髪色、体型を独立して選べる構成へ拡張する。基準ハンターAは既定プリセットとして残す。本書は技術上の境界と受入条件を定める。選択肢の名称・種類・見た目は[作品仕様](customization_spec_v2.md)と同納品のカタログを参照する。

## 1. 現行との差

| 現行 | 実装時に必要な変更 |
| --- | --- |
| 全身の絵を共通アトラスへ焼いている | 肌・髪・衣服を区別し、選択した領域だけ色を変える |
| 耳・親指・髪束は固定色の立体 | 肌色・髪色の共通パラメータへ接続する |
| `BODY_RANGES` はグローバル可変 | 各モデル固有の表示区分として保持する |
| 兜装着時は髪束と耳を同時に隠す | 髪型の兜用形状と耳を個別に制御する |
| 防具位置・頭の輪郭は固定 | 体型と頭形状に応じて防具を合わせる |
| セーブschema 3に外見項目なし | schema 4へ移行し、外見を保存する |

根拠: 本体[S1][S1]、リグ[S2][S2]、防具[S4][S4]、保存[S5][S5]。以下のチェック項目は受入予定であり、達成済みの一覧ではない。

## 2. 肌色とUVの契約

- 全身材質への一律の色乗算を使わない。顔・首・露出した腕・手だけを指定するskin maskを用意する。衣服・革・金具・髪・眉・眼球へ肌色を混ぜない。
- 現行アトラスと同じ配置・同じ`uv1`を使用する。`head`区画全体を肌扱いにしない。頭区画には髪や顔の各要素が含まれる。[S2][S2] [S3][S3]
- 肌の下地は色と陰影を分けて調整できるものにする。元の肌色へ単純に掛け算するだけで全肌色を成立させた扱いにしない。濃淡の両端で、唇・鼻・目周辺の立体感を確認する。
- マスクは色ではなく領域を表す値として扱う。境界とUVの余白を整え、縮小表示でも襟・袖口へ肌色がにじまないことを確認する。
- 耳・親指の固定`SKIN`色も同じ肌色パラメータから求める。顔だけ色が変わり耳や手が旧色のままになる状態を残さない。陰影用の濃淡は保持できる。[S1][S1]
- スウォッチはUIの基準色であり、照明後の画面RGBや肌色の実測値ではない。A固有の肌色は保持し、近いパレット番号へ丸めない。赤み・黄みの調整も保存して再現する。
- 肌色変更だけで人体形状を再生成しない。現行Lambertでの領域着色と、将来のPBR導入を別作業として扱う。[S2][S2]

## 3. 髪・頭皮・兜

- 頭皮と顔の下地を髪型から分離する。髪束だけ交換して旧髪型の生え際や頭頂の絵が残らないこと。坊主や額の広く出る髪型も同じ条件で確認する。
- 髪型ごとに通常形と兜用形、または兜時の表示区分を定義する。前髪・側頭部・えり足・結び目のうち何を残すかを明示する。
- 兜用形でも肌色・髪色の選択を維持する。髪色変更で眉を連動させる場合は別領域として定義し、肌マスクへ混ぜない。
- 長髪は肩・フード・背負い武器との干渉を確認する。揺れ骨がない段階では、静的なまとまった形としての限界を明示する。
- 現在の`BODY_RANGES.hair`には耳も含む。髪・耳・外套を別区分にし、生成結果と一緒にモデルごとの範囲を返す。共有の可変範囲を別個体から参照しない。[S1][S1] [S2][S2]
- 編集用プレビューとゲーム本体を同時に生成しても、片方の髪交換が他方の非表示範囲を壊さないこと。三角形数が変わる髪型でも確認する。

## 4. 体型・顔と共通骨格

先行版は身長1.75m、17主要骨、肩・股関節の位置、手足の関節長、4 socketを維持する。現行`REST`を共通基準とし、頂点の位置と断面形状で厚み・輪郭を調整する。[S8][S8] [S9][S9]

- 女性・男性・中性的なプリセットは初期パラメータの組合せとする。肌・髪・体格の選択を特定プリセットへ固定しない。
- 体格、筋肉量、胸郭、腰、骨盤周囲、腕・脚の太さは、制作確認を通した範囲で調整する。肩幅の見え方と肩関節間の距離を混同しない。
- 顔プリセットも頭の骨位置を維持する。頭の輪郭が変わる場合は、顔の絵だけでなく耳・髪のfit・兜のfitを揃える。
- 体型の8軸は肩の外側の量感・胴の厚み・胸部の量・腰幅・腹部の量・手脚の太さ・筋肉量・柔らかさ。UIと保存値は0〜100とし、形への変換とA初期値を版管理する。全軸50をAと仮定しない。
- 顔の小幅な調整は、顎幅・頬の厚み・鼻幅・口元・目の間隔を対象にし、頭骨位置を変えず輪郭と顔の絵を整合させる。眉は独立領域、目色は虹彩だけへ適用する。
- 各スライダーの単独上下限に加え、複数の上下限を組み合わせた形を確認する。最大値どうしで胸・腕・腰板が交差する範囲は公開しない。
- 人体だけ太くして服や防具を旧形状のまま残さない。衣服にも同じ体型情報を適用し、縫い目や革帯の位置を保つ。
- `HunterRig.root`の拡大縮小で体型を変えない。武器とsocketまで移動・拡縮され、表示と判定の整合を崩すため。[S2][S2]

## 5. 防具fitと更新キー

現在の`torsoZ`、`HEAD_SHAPE`、`HELM_SHAPE`、板の中心と幅は固定値である。任意体型へ自動で合う実装ではない。[S1][S1] [S4][S4]

- 身体・頭から共通のfit情報を作り、衣服・兜・5部位防具へ渡す。身体と防具が別々の係数で広がらないようにする。
- 柔らかい下地は体に沿わせ、硬い岩板・金具は配置と傾き、必要な寸法で合わせる。体型に応じて板全体をゴムのように変形させない。
- 肘内側、手首、膝、股、背中の武器経路を空ける。服と防具の境界に穴を作らず、右腰袋と左右非対称の板配置を維持する。
- `setArmor`は現在、装備段階だけのキーで同一判定する。装備が同じでも体型・頭形状が変われば更新するよう、fitの版と値を更新キーへ含める。[S2][S2]
- 全身一式だけでなく、各部位だけの交換・混在・取り外しを確認する。髪や外套の復帰も体型と髪型の現在値に合わせる。

## 6. 保存schema 3→4

外見設定は独立した`appearance`領域に置く。必要項目は外見データ版、体型・顔のプリセットID、肌色と赤み・黄み、髪型・髪色、8軸の体型調整、顔の微調整、眉型、眉色の髪連動／独立設定と独立色、目色。IDは選択カタログと揃え、表示名をIDとして保存しない。

- `newSave`へ基準Aの既定外見を追加する。`MIGRATIONS`へ3→4を1段追加し、旧データの所持品・装備・進行を維持する。[S5][S5]
- 外見の初期値を乱数で決めない。移行には校正済みのA初期値を使い、未校正の値を50や近似色へ置換しない。校正までは現行Aの表示を維持し、移行を公開しない。
- `validateSave`でオブジェクト形、ID文字列、有限数、許可範囲を確認する。不正値をGPUや形状生成へ渡さない。保存時の値と描画側の解決値を分ける。
- 旧データは`saveManager`の移行前バックアップを使って保管する。新しいschemaのデータを旧版が読めない時は、現在の上書き防止を維持する。[S6][S6]
- 書き出し・取り込み・バックアップ復元でも外見を往復できること。通常起動だけの移行で終わらせない。

### 未知IDを失わない

形が正しいが未収録の髪型・顔・体型IDは、元の保存値を残し、表示だけ既定素材へ代替する。素材が戻れば元の設定で描けるようにする。代替したIDを自動保存して置換しない。

編集確定は現在の保存データへ変更した項目だけを適用し、未編集の未知IDや対応外フィールドを落とさない。未知の外見データ版は、読み込める既知の値へ勝手に変換・確定しない。描画用代替を使い、該当領域の書換えを保留する。新旧アプリ間で、別項目を編集しただけで将来の情報が消える状態を避ける。

## 7. 一時編集と確定保存

- 編集画面は保存値を複製したdraftを持つ。スライダーとプレビューはdraftだけを更新する。
- 「決定」で検証し、`SaveManager`のrevision付きcommitを1回実行する。成功後に保存済み表示とゲーム側の確定外見を更新する。[S6][S6]
- 「キャンセル」はdraftを破棄し、編集開始時へ戻す。「この項目を戻す」は当該項目だけを編集開始時の値へ戻す。「全体をAへ戻す」はdraftにA一式を適用する。保存は「決定」時だけ行う。
- 保存失敗はdraftを保持し、再試行できるようにする。成功扱いにしない。他タブとの競合では最新状態を読み、古い外見や所持品を一括上書きしない。再適用する変更を保持する場合も、競合を表示する。
- 非同期で髪素材を読み込む場合は、古い読み込み完了が最新選択を上書きしないようにする。利用できない素材を確定可能にする場合は代替表示を明示する。

## 8. 能力差を生じさせない境界

- simulationは外見から能力値を求めない。HP、スタミナ、移動速度、攻撃力、防御力、攻撃窓、リーチ、武器軌道、被弾判定を共通にする。
- 現行の被弾カプセルは共通の`PlayerTuning.height/radius`を参照している。この経路へ体型値を接続しない。[S7][S7]
- 同じ入力・装備・状況で外見だけを変えた時、戦闘計算の結果が一致することを確認する。
- 共通判定から見た目が大きく離れる体型は、単に「能力差なし」で済ませない。許可する形状範囲を調整し、見た目と被弾の不自然な差を抑える。

## 9. 身長拡張の開始条件

身長変更は先行版の固定1.75mとは別の実装段階とする。全身scaleを追加しただけで公開しない。

- 異なる骨長で手・足のIKと既存動作を解ける。
- 主手・添え手・弓の引き手が武器に合い、固定した武器リーチと攻撃軌道を保てる。
- 接地、歩幅、前転、カメラ、地形との関係を確認できる。
- 全装備のfitと共通被弾カプセルに対する見た目を確認できる。
- 最小・最大身長と体型の組合せで上記を通せる。

この条件が未確認の段階では身長スライダーを出さない。固定身長でも体型・顔・髪・肌の選択は先に提供できる。

## 10. 性能と受入

色替え、髪交換、体型変更を異なる更新単位として扱う。毎フレーム全形状を生成せず、変更時だけ更新する。連続操作中は更新頻度を制御し、不要なgeometry・texture・materialを解放する。全組合せを無制限にキャッシュしない。

| 必須確認 | 合格条件 |
| --- | --- |
| 肌色の両端 | 顔・首・腕・手・耳・親指がそろい、衣服へ着色しない |
| 髪と兜 | 旧髪の絵や毛束が残らず、着脱して正しい形へ戻る |
| 複数プレビュー | 他個体の髪・耳・外套の範囲を壊さない |
| 体型と防具 | 同じ装備のまま体型を変えてもfitが更新される |
| 代表動作 | 振り上げ・両手握り・弓・しゃがみ・前転・納刀で確認する |
| 保存 | 旧版移行、確定、取消、再読込、競合、失敗、import/restoreを確認する |
| 未知ID | 代替表示後の別項目編集・書出しでも元情報が残る |
| 能力 | 外見のみ変更しても同条件の戦闘計算が一致する |
| 実機 | iPhone/iPad SafariとPCで戦闘場面の負荷を測る |

新規キャラメイク、肌マスク、髪素材、体型fit、保存移行、実機性能は本納品では未検証。面数・材質数の目標だけで実機合格としない。ゲームコード・既存データを変更せず、実装担当へ契約を渡す。
