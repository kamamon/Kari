# キャラメイク 状態・保存・接続契約 v1

確認日: 2026-11-25（日本時間）／基点: `main` `4851d57ecc24c8fd127508b084999cec5d0e975f`（v0.22.0）。

**機能の設計提案であり、以下の画面・API・保存領域は未実装。** 操作の詳細は[機能仕様](character_creator_function_spec_v1.md)、外見の定義は[外見仕様](customization_spec_v2.md)、[カタログ](appearance_catalog_v1.json)、形状と材質は[実装契約](implementation_contract_v1.md)を参照する。本書はユーザーの追加依頼を受け、編集機能の状態とデータ保護を具体化する。名前・声・身長変更は追加しない。

## 1. 現行への接続位置

| 現在存在する処理 | 追加する接続・注意 |
| --- | --- |
| `main.ts`で読込、`SaveManager.open`、「はじめる」、`new App`、`app.start` | 初回判定に必要な読込結果を保持し、App生成後に専用overlayを開いてから最初のフレームを開始。音声開始のユーザー操作は維持 |
| `App`は里または旧一覧式の拠点を生成 | 新規プレイだけ初回案内。既存セーブの起動を毎回キャラメイクへ戻さない |
| `BaseScreen`の`chest`区分に武器・防具・データ欄 | 「見た目を変える」を追加し、費用なしで再編集。里と一覧式拠点の双方から入れる |
| `setOverlay`はbase/resultのみ、停止判定も編集画面を持たない | 専用overlay・停止条件・入力遮断を追加。閉じる時は元の装備箱へ戻し、誤って戦闘入力を有効にしない |
| `saveChanged`は武器・防具の差だけを見る | 外見の変更検知と表示更新を追加。外見反映のために`createSession`を呼ばない。同関数は報酬精算を伴う |
| `Menu`のスライダーは`SettingsStore`を即更新 | そのまま外見編集へ流用しない。メニュー設定と外見draftを分離 |

現行の入口・画面・保存処理は[S1][S1] [S2][S2] [S3][S3] [S4][S4]。`openCharacterCreator`や`commitAppearance`という既存APIはない。必要なら新設する名前であり、呼ぶだけで動くものとして扱わない。

`SaveManager.open`には新規作成・既存読込・読めないデータの代替開始があるが、その区別を専用の初回フラグとして公開していない。新しい起動コンテキストを追加し、`revision === 0`だけで初回と判定しない。memory/readonlyの一時データを新しい永続セーブと誤認しない。[S6][S6]

## 2. セッションと保存対象の識別

| 値 | 用途 |
| --- | --- |
| `entrySnapshot` | 入室時の確定外見。「編集開始値へ」とbefore表示の不変の基準 |
| `baseline` / `baseRevision` | 保存時に最新値と比較する基準。競合解決後は更新する |
| `draft` / `dirtyPaths` | 編集値と、baselineから実際に変えた外見のパス。明示的な削除も区別 |
| `categoryBase` | 最後に明示適用した見本Pと、そのカテゴリ初期値。値を校正データから解決する |
| `sessionId` / `previewGeneration` | 画面の生存期間と、非同期プレビューの世代を識別する |
| `locks` / undo / redo | ランダム対象の固定と、セッション内の履歴。能力値へ渡さない |

現行にあるのは`slotId = "main"`とrevisionであり、保存個体を一意に識別する永続IDはない。狩猟の`runId`も代用できない。[S2][S2] [S5][S5]

**追加案:** 確定セーブに`saveInstanceId`を持たせる。通常更新では維持し、新規作成・全体import/reset/restoreでは新しく発行する。取り込んだファイルのIDをそのまま端末内の識別子に使わない。編集対象キーはゲームのnamespace・slotId・saveInstanceIdの組とする。

初回で確定セーブがまだ存在しない場合は、別領域に`pendingNewSaveId`を発行し、対象を「このslotが空であること」と結び付ける。本保存は決定時だけ行い、その時もslotが空であることをtransaction内で再確認し、pendingNewSaveIdを新しいsaveInstanceIdとして採用する。別タブが先に作ったセーブへ初回draftを混ぜない。既存セーブへのID追加は保存schema移行の仕事であり、外見draftの自動確定とは別に扱う。

## 3. 状態・イベント・guard・副作用

dirty、比較表示、素材の準備状態は付随値とし、全ての組合せを別状態へ増やさない。

| 状態／イベント | guard | 遷移と副作用 |
| --- | --- | --- |
| 閉じた状態／初回・拠点から開く | 狩猟中でない、他の保存操作中でない | 読込中へ。保持中の操作入力を解除し、戦闘入力を遮断。対象ID・確定値・入室元を取得し、独立プレビューを準備 |
| 読込中／復帰draft発見 | 対象ID・データ版を検査できる | 復帰確認へ。自動適用も本保存もしない |
| 読込中／準備完了 | 解釈できる外見、基準取得済み | 編集中へ。entrySnapshot・baseline・draftを分離 |
| 編集中／変更・履歴・見本適用 | 保存中でなく、許可された外見項目 | draft更新。新世代でプレビュー要求、dirtyを再計算 |
| 編集中／確認へ | 対応版で形式検証を通る | 確認中へ。現在のdraftを固定して確認画面に表示。素材が未準備なら決定は無効 |
| 確認中／編集へ戻る | 保存を開始していない | 編集中へ。draftと履歴を維持し、書き込まない |
| 確認中／決定 | 確認したdraftが現在値と一致し、変更部分の校正・必要素材の準備を満たす | 保存中へ。二重押下を防ぎ、対象ID・revision付きで1回保存 |
| 保存中／成功 | transaction完了 | draft控えを削除し閉じる。確定外見のみ里へ反映 |
| 保存中／失敗・競合 | 失敗種別を区別 | 通信・容量等は編集中へ戻しdraft保持。revision差は競合確認へ |
| 編集中・確認中／キャンセル | 保存中でない。dirtyなら破棄確認 | draftとその復帰控えを破棄し、入室元へ戻る。確定値は変更しない |
| 対応外データ／編集要求 | 将来版を解釈できない | 閲覧・原本退避のみ。該当外見の確定を禁止 |

初回のキャンセルは未保存のまま初回入口へ、拠点再編集のキャンセルは元の装備箱へ戻る。初回の決定成功は里へ進み、再編集の成功は装備箱へ戻る。

既存セーブでdirtyが空なら確認後の決定で書かずに閉じる。未作成slotの初回保存は別扱いとする。保存中に閉じる操作や追加の決定を受けない。成功を先に表示しない。readonlyでは元の保存データに触れず、memoryでは「この起動だけの適用」と明示した別動作にする。memoryでの適用を永続保存成功と表示しない。既存のSaveModeとtransactionの扱いを基礎にする。[S6][S6] [S7][S7]

## 4. revision競合の再適用

現在の`SaveManager`は競合時に最新データへ読み替えて停止する。自動的に外見差分を再適用するAPIはない。以下を新しい外見専用処理として設計する。[S6][S6]

1. 最新canonicalを読み、保存対象IDが同じか確認する。IDが違えば再適用せず、別セーブとして止める。
2. `dirtyPaths`ごとにbaseline・draft・最新値を比較する。最新＝baselineなら変更可能、最新＝draftなら既に反映済み、それ以外は競合として表示する。存在しない値と明示的削除を区別する。
3. profile、dataVersion、校正版、関連presetなどの前提も比較する。肌だけ同じでも、profileが変わっていれば無条件に再適用しない。
4. 安全に重ねられる変更と、選択が必要な変更を画面で示す。利用者が「最新に自分の変更を適用」を選んだ後に、新baselineとdraftを作る。entrySnapshotはこの操作で書き換えない。
5. **最新canonicalを土台に、許可したappearanceパスだけを変更する。** 古いSaveDoc全体や古い装備・所持金・進行をコピーしない。合成後の外見と素材・fitを再検証する。
6. 新revision・同一IDをtransaction内で再確認して保存する。再び競合したら再確認へ戻し、無制限に自動再試行しない。

表示上のfallback値をbaselineに使わない。未知IDと拡張項目は保存された生値で比較する。「決定」は変更全体を1回で確定する操作であり、競合項目だけを黙って捨てて部分成功にしない。

## 5. profile・未知ID・素材の準備

カタログの`legacy_hunter_a_v1`は既存Aの形・材質を保持する契約、`custom_hunter_v1`はIDと調整値を明示保存する契約である。どちらも現行runtimeへの統合は未実装。[カタログ](appearance_catalog_v1.json)

schema 3→4で外見欠落をlegacyとして表す処理と、legacyからcustomへ数値化する処理を分ける。前者はAを変形させない。後者は変更しない領域も含めてAを再現できる校正値・素材が揃った時だけ行い、全軸50や近似肌色で埋めない。校正前はAのまま進める経路を残す。これは旧実装契約の校正条件を、customへの変換条件として明確化したもの。

新しい選択を確定できる条件は、対応profile、有限で範囲内の値、校正済みの変換、必要素材の制作・fit確認・読込成功がそろうこと。現在のカタログの`authoring_draft`や`calibrated:false`を、そのまま選択可能な完成素材として使わない。未制作・読込失敗の見本は紹介表示できるが、確定を無効にする。

以前から保存されている未知IDは生値を保持し、表示だけ代替する。未編集の未知IDを残したまま別の対応項目を変更することと、未制作IDを新しく選んで確定することを区別する。将来のappearance版は書き換えず、原本を保つ。レシピやお気に入りから未対応値を持ち込む場合も、代替値への自動置換・確定はしない。

非同期読込はsessionIdとpreviewGenerationに結び付ける。閉じた画面・旧選択の完了通知を捨て、不要な素材を解放する。最後の見本が表示されていても、現在のdraftに必要な素材がreadyでなければ決定できない。before比較の表示素材をafterのready判定に流用しない。

## 6. 編集操作・履歴・比較

| 操作 | draftへの効果 |
| --- | --- |
| カテゴリ初期値へ | categoryBaseの当該カテゴリだけへ。未知見本や未校正で解決不能なら無効。全50にしない |
| 編集開始値へ | entrySnapshotへ全draft復帰。現在の本保存を巻き戻す操作ではない |
| A全体へ | draftをlegacy Aへ。決定するまでは里の姿を変えない |
| before/after | 同じカメラ・照明・表示装備でentrySnapshotとdraftを比較。値・履歴を変更しない |

categoryBaseは全体見本Pを明示選択した時だけ更新する。個別のB/F選択、お気に入り・レシピ適用、「A全体へ」「編集開始値へ」は基準を維持する。外見の由来を表すsourcePresetIdから勝手に更新しない。基準をAへ変える操作はP01の明示選択とする。

Undo/Redoは編集セッション内で最大50操作。ドラッグ開始時と終了時の差を1操作として記録し、途中のinputごとに積まない。pointercancelは開始値へ戻す。ランダム、見本、リセット、お気に入り、レシピの適用も各1操作。全体P選択のUndo/Redoは、外見とcategoryBaseを同時に操作前後へ戻す。変化なしは履歴なし。Undo後の新編集でRedoを消す。カメラ・比較・固定チェックは外見履歴に含めない。

カテゴリ固定は**ランダムにだけ適用**し、手動編集・リセット・見本適用を禁止するロックにしない。固定したカテゴリは関連値ごと保持し、未固定だけを校正済みpreset集合から選ぶ。眉が固定され、眉色が髪に連動している場合は、その抽選だけ髪色も保持して理由を表示する。連動を勝手に独立色へ替えない。未制作、未対応、未確認の組合せを候補に含めず、連続値を無制限に乱数生成しない。候補がなければ理由を表示し、値・履歴を変えない。ランダムによるprofile変換も前節の校正条件を守る。

## 7. お気に入り6枠と外見レシピ

お気に入りは端末のキャラメイク専用sidecarへ6枠保存する。確定セーブと別に管理し、登録してもcanonical appearanceを変えない。全体セーブのimport/reset/restoreで自動削除しない。登録対象は明示したdraft外見であり、装備・所持金・進行・保存対象IDを含めない。上書きは対象枠を示して確認する。保存失敗は未保存表示とし、レシピ書出しで持ち出せるようにする。

お気に入り適用は検証後にdraftへ1操作で入れる。未知値を含む枠は原本を残して対応状況を示し、未制作素材を新規確定する抜け道にしない。枠更新にもローカルrevisionを持たせ、他タブの登録を古い一覧で上書きしない。

外見レシピは新しい専用formatとversionで識別する。提案値はUTF-8で最大65,536bytes（64KiB）。文字数でなく読込前のファイルbyte数を確認する。既存の`parseImport`は全セーブを受ける処理なので、この用途へ直接接続しない。[S5][S5]

- 許可するのはformat、recipeVersion、appearanceと必要なカタログ版だけ。全SaveDoc、通貨、装備、進行、保存ID、名前・声・身長を受け付けない。
- JSON構造、対応版、型、有限数、範囲、ID、profile、素材準備を検証する。外見以外のキーや任意パスをcanonicalへ書く処理を持たない。
- 不正・大きすぎる・将来のrecipe版は適用前に止める。未知IDや将来のappearance版は原本を失わず、対応前の確定を禁止する。
- 読込直後に本保存せず、内容と不足素材を表示してからdraftへ適用する。書出しは外見データだけを直列化し、カメラ・固定チェック・履歴を混ぜない。

## 8. 中断draftと復帰

現行DBにはslotsとbackupsがあるが、キャラメイクのdraft・お気に入り領域はない。新しいsidecarを用意し、canonical保存のAPIを自動控えに使わない。[S7][S7]

控えには対象キー、draft、locks、categoryBase、旧baseline・baseRevision、データ版、更新時刻を保存する。ジェスチャー完了後のdebounceで書き、`visibilitychange`では終わった操作をbest effortで控える。終了イベントだけを唯一の保存機会にしない。OSの強制終了まで保証した表示をせず、失敗時は「下書き未保存」と示す。Undo/Redo履歴は控えへ継承しない。

復帰時は同一namespace・slot・保存IDを検査する。revisionが一致すれば復帰内容を確認して再開。不一致なら前述のbaseline比較を使い、差分と再適用結果を確認してから再開する。別保存IDなら元のdraftとして隔離し、今のセーブへ自動的に混ぜない。初回draftはpending IDが対応し、slotが空なら復帰候補にする。同じpending IDのcanonicalが既に存在する場合は初回保存の結果として照合し、反映済みか競合かを判別する。別IDには適用しない。

保存中に中断した場合は、先に同一保存IDの最新値を読み直す。変更対象が全てdraft値になっていれば既に反映済みとして控えを消し、再commitしない。異なる値があれば復帰・競合確認へ進み、保存の成否を推測して表示しない。

再開は新しい編集セッションとする。現在の確定外見を新entrySnapshot・baseline、確認した復元値をdraftとし、locksを復元する。Undo/Redoは空から始める。beforeと「編集開始値へ」は再開時の確定外見を指すと表示する。復帰・debounce・非表示化のいずれでも本保存を自動commitしない。決定成功または明示破棄後だけ対象のdraft控えを消す。お気に入りは消さない。

## 9. 必須受入

| 確認 | 合格条件 |
| --- | --- |
| 初回と再編集 | 新規・既存・memory・readonlyを区別し、両拠点から再編集できる |
| 入出力 | 編集中は戦闘入力停止。初回取消は初回入口、初回決定は里、再編集終了は元の装備箱へ戻る |
| 保存 | 二重押下、失敗、取消でcanonicalを誤更新せず、成功後だけ姿が変わる |
| 競合 | 別項目なら差分確認後再適用、同項目なら選択。装備・通貨・進行は最新を維持 |
| 保存対象 | import/reset/restore後や別タブの新規作成へ旧draftを混ぜない |
| profile | legacy Aを保持し、未校正のcustom変換を止める |
| 素材 | 遅い旧応答、読込失敗、未制作素材で誤プレビュー・誤確定しない |
| ランダム・履歴 | 固定対象を守り、未制作除外。drag1回＝1履歴、最大50 |
| お気に入り・レシピ | 6枠、64KiB、版・型・範囲を検証し、外見以外へアクセスしない |
| 復帰 | 同revisionと不一致を分け、値とlocksだけ再開。自動本保存なし |

本書はコードを読んで作成した契約であり、これらの受入は未実施。既存コードは変更していない。実装時の保存単位・素材準備状態・未対応データの扱いを先に確定し、完成した画面と実機の結果を別途記録する。
