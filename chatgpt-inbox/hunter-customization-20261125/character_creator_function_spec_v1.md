# キャラメイク機能・画面操作設計 v1

2026-11-25／霧境の狩人 — VEILBOUND HUNTERS／Claude向け設計提案

## 1. 目的と今回の範囲

利用者の追加指示「キャラメイク機能も設計して」に対応し、外見を選び、試し、戻し、保存するまでの操作を定める。見た目の種類は[外見仕様](customization_spec_v2.md)と[カタログ](appearance_catalog_v1.json)をそのまま使う。本書では選択肢の数やIDを増やさない。以前の「この項目を戻す」という表現は、本書の三つの明確な復帰操作へ置き換える。

**機能、回転できる本物の3Dプレビュー、肌マスク、髪交換、体型への防具調整、保存処理は未実装である。** 原画や画面見本は操作・制作の参考であり、動くモデルの完成や実機合格を示さない。カタログの仮数値は、実際のモデルで校正してから公開する。

全員が成人の狩人で、先行版の身長は1.75m、骨位置・長さと武器接続位置は共通とする。女性的・男性的・中性的という見本の説明によって、肌、髪、顔、体型を制限しない。外見による能力差も付けない。名前の新規入力を必須にせず、ゲームに既にある呼称を使う。声、傷、化粧、身長変更は次段階とし、今回の入力欄には加えない。

## 2. 入り口と二つの作成経路

保存のない新規開始では、ゲームへ入る前に「見た目を選ぶ」を開く。既定選択はP01の基準ハンターA。成人見本6種を同じ大きさで並べ、「あとから里で無料で変えられます」と案内する。既存セーブを読み込んだ人には作り直しを強制せず、その外見を維持する。外見項目のない旧セーブはAを再現する。

手早く始める人は、見本をタップし「この見た目で進む」を押す。これは最終確認へ進む操作で、その時点では保存しない。確認して「この見た目に決定」を押すと初回の外見を保存し、ゲームへ進む。

細かく作る人は「詳しく編集」を押し、体型・肌・髪・顔の各欄を行き来する。全項目の変更は必須ではなく、見本のまま残せる。編集中に全体見本を選び直す場合は、今の内容から何が替わるかを表示して「この見本を適用」で下書きへ入れる。

再編集は拠点の装備箱の「見た目を変える」から開く。費用と消耗品は不要。開始時に確定外見を読み、編集終了後は同じ装備箱へ戻る。所持品、武器、防具、通貨、進行、里での位置を維持する。狩猟の途中ではこの入口を表示しない。

## 3. 端末ごとの画面構成

iPhoneの横画面を主とし、左に大きなプレビュー、右に選択欄、下に「キャンセル」「確認へ」と履歴操作を置く。選択欄だけを縦にスクロールでき、顔を見ながら髪や色を替えられる。端末の切欠きとホーム操作領域へ重要ボタンを重ねない。押せる範囲は44 CSS px以上を設計目標とし、小さな色丸でも周囲を含めて押しやすくする。

縦画面では上にプレビュー、下に選択欄を積み、最下部の操作を固定する。「縦向きでも編集できます。狩りは横向きで始めます」と案内する。ゲーム本編の縦向き時の扱いと、編集画面の配置を分けて実装する。向きを変えても選択値、固定、履歴、編集中のカテゴリを保つ。

iPadは十分な横幅がある場合に左右配置とし、縦でもモデルを見失わない高さを確保する。PCは同じカテゴリ構成を使い、マウスとキーボードで全項目を操作できる。Tabで移動、Enterで選択、矢印でスライダーを調整する。選択中は色だけで示さず、チェックと名称も表示する。

上部には「見本・体型・肌・髪・顔・保存」のカテゴリを置く。「保存」にはお気に入りと外見レシピをまとめる。編集中は「決定するまでゲームの姿は変わりません」と示し、確定済みと下書きを取り違えさせない。

## 4. 変更できる項目

IDは制作・保存上の共通規格として維持する。通常の画面には名称を表示する。

| 区分 | 既存の選択肢 | 操作 |
|---|---|---|
| 全体の見本 | P01〜P06、6種 | 全体を見て、適用してから細部へ進む |
| 体型 | B01〜B04、4種 | 細身・標準・筋肉質・ふくよかを選び、8軸を調整 |
| 肌 | S01〜S12、12色 | 色を選び、赤み・黄みを調整 |
| 髪型 | H01〜H16、16種 | 額、側頭部、後頭部が分かる見本から選択 |
| 髪色 | C01〜C12、12色 | 髪型を維持して色だけ変更 |
| 顔 | F01〜F06、6型 | 輪郭を選び、5軸を調整 |
| 眉 | R01〜R06、6種 | 形と、髪に連動する色／独立した色を選択 |
| 目 | E01〜E07、7色 | 虹彩の色を選択 |

体型の8軸は肩幅、胴の厚み、胸部の量、腰の幅、腹部の量、手脚の太さ、筋肉量、柔らかさ。顔の5軸は顎幅、頬の厚み、鼻の幅、口元、目の間隔。どちらも0〜100をUI規格とする。肌の赤み・黄みは−100〜100。これらは身長やcmを表す数値ではない。

スライダーには名称、現在の数値、−／＋を併記する。ドラッグが難しい時は1ずつ増減し、数値欄へ直接入力できる。範囲外の値は「0〜100で入力してください」のようにその場で伝え、確定前の正しい値を残す。髪型と髪色、顔と肌など、別項目を勝手に連動変更しない。

H01・C02・F01は採用Aに対応する。Aを開いただけで全軸50や近似の肌色へ変換しない。校正した数値へ対応できない項目は「準備中」とし、誤った値を表示しない。制作途中の画像には「参考画」と明記し、未制作の3D資産を選択可能な完成品に見せない。

## 5. プレビューの操作

モデルの表示部分を左右へなぞると回転し、選択欄をなぞると一覧が動く。プレビュー外のスクロールでモデルを回さない。二本指の拡大縮小に加えて、寄る・引くボタンを置く。「顔／全身」「正面／後ろ」で、操作に慣れていなくても同じ位置へ戻せる。

髪・顔のカテゴリへ初めて入った時は顔へ寄り、体型では全身を見せる。その後に手で変えた角度と距離は、色や髪を替えるたびに勝手に初期化しない。正面と後ろで同じ人物を見られることが前提で、静止画の切替を3D回転として扱わない。

光は「均一な光」を標準とし、「里」「狩場」の確認用照明へ切り替える。照明を替えても選択した肌色は変更しない。衣服は「初期服／現在の装備」を表示し分ける。確定装備を維持したまま、確認用の見せ方だけを替える。

「兜で確認」で髪の収まりを見て、解除すると選んだ通常髪へ戻る。兜未所持時は、確認用のモデルが用意できた場合に「参考の兜」と表示する。モデルがなければ確認ボタンを「準備中」にする。

## 6. 項目を固定してランダムにする

体型、肌、髪型、髪色、顔、眉、目色ごとに「ランダム時に固定」を置く。体型の固定には8軸、肌には赤み・黄み、顔には5軸を含める。固定はランダム操作にだけ働き、手動選択、見本適用、リセット、お気に入り適用は行える。

例えば顔と肌を固定して「ランダム」を押すと、その顔と肌を保って髪や体型を試せる。固定した眉が「髪に合わせる色」の時は、同じランダム操作で髪色も保持し、「眉色に連動して髪色も固定」と説明する。設定を勝手に独立色へ変更しない。

抽選対象は使用可能な資産と、校正済みの見本・検証済み調整域に限る。体型8軸を無制限に上下限まで抽選しない。見本の女性的・男性的・中性的という分類を、抽選の制限条件にしない。全て固定されている時は「固定されていない項目がありません」と表示する。

一度の抽選は一つのUndoで直前へ戻る。何度でも試せるが、決定まではゲームへ反映されない。現在のカタログは校正前なので、その仮数値をそのまま実行用ランダムへ接続しない。使用できる範囲が未確定なら「ランダムは準備中」とする。

## 7. Undo・Redo・比較と三つの復帰操作

Undo／Redoは50操作を保持する。スライダーは押してから離すまでを1操作、数値入力は確定を1操作とする。ランダム、全体見本、お気に入り、レシピの適用、リセットも各1操作。元に戻した後に新しい変更をしたら、やり直しの枝は消す。50操作を超えた分は古いものから履歴外になる。

モデル回転、照明、比較表示、固定の切替は外見変更の履歴に入れない。画面回転や割込みでドラッグが途切れた時は、そのドラッグ開始前の値へ戻し、途中の値を履歴へ残さない。PCのCtrl／Command＋ZとRedo操作を使え、数値欄の入力中はその欄の編集を優先する。

比較は「編集開始時／現在」の切替とする。両方を同じ角度・光・装備で見せ、比較を見ただけで下書きは替えない。編集中に全体見本を替えても、編集開始時の比較対象は維持する。

| 操作 | 戻す範囲と基準 |
|---|---|
| カテゴリ初期値へ | 最後に明示選択した全体見本Pの、そのカテゴリだけ |
| 編集開始値へ | 今回の編集を開いた時の外見全体 |
| A全体へ | 採用Aの顔・髪・肌・体型へ全体を戻す |

例：P02を適用し、体型B03へ替えて筋肉量を調整した後、体型の「カテゴリ初期値へ」を押すと、P02に含まれるB02とその初期値へ戻る。B03や顔Fの選択だけでは基準Pは替わらない。ボタンの補足に「見本○○の体型初期値」と表示する。お気に入り・レシピの適用も、現在の基準Pを維持する。

「編集開始値へ」「A全体へ」も基準Pは維持する。P01を全体見本として明示選択した時に基準P01へ替える。全体見本の選択をUndo／Redoする時は、外見と基準Pを一緒に戻す。

初期値を解決できない見本では、理由を表示してカテゴリ初期化を無効にする。全軸50で代用しない。全体復帰は変更される範囲を確認してから下書きへ適用し、Undoで戻せる。どの復帰操作も本保存を直接変更しない。

## 8. お気に入りの見た目6枠

「保存」カテゴリに「見た目1〜6」の6枠を置く。現在の下書きを「お気に入りに登録」で保存でき、ゲームの姿を確定する前にも候補を残せる。記録するのは外見だけで、所持品、装備、通貨、進行を含めない。

お気に入りは端末のキャラメイク専用の保存領域とし、本編のセーブとは分ける。本編の保存データを取り込む、初期化する、控えから戻す操作で、自動的に6枠を消さない。別端末へ渡す時は外見レシピを使う。

空き枠へ保存すると「お気に入りに登録しました。ゲームの姿はまだ変わりません」と表示する。使用中の枠は「見た目3を今の外見で上書きしますか？」と確認し、「上書きする／やめる」を選ぶ。登録失敗は成功扱いにせず、下書きと従来の枠を保持する。

呼び出す時は枠を選び、見本を確認して「編集中へ適用」を押す。全外見を一度のUndoで戻せる単位として入れる。固定項目も手動適用の対象になる。未対応値の新規持込みは第9節の確定制限に従う。履歴のUndoは下書きへ作用し、お気に入りの上書き自体を巻き戻さない。枠の削除は対象を明記して確認する。

## 9. 外見レシピのJSON書き出し・読み込み

「外見レシピを書き出す」は編集中の外見だけをJSONへ出す。「現在の確定見た目」を出す場合は対象を切り替える。外見の版、選択ID、調整値と必要な互換情報を持ち、通貨や装備を持ち出さない。書き出しただけでゲームの姿を確定しない。

「外見レシピを読み込む」で端末のファイルを選ぶと、内容を確認し、先に専用プレビューを開く。読み込んだ瞬間には下書きを置き換えない。「編集中へ適用」で入れ、「やめる」なら元の編集を続ける。適用全体は1操作としてUndoできる。

本編の保存データを選んだ時は「外見レシピではありません。見た目だけを書き出したファイルを選んでください」と案内する。形式が不正なら「読み込めませんでした。編集内容は残っています」と表示する。お金や装備の情報をキャラメイクへ取り込まない。

未知IDの扱いは入口で区別する。既存の確定セーブにある未知IDは元値を残し、対応済みの別項目を編集・保存できる。レシピやお気に入りから新たに持ち込む未対応IDは、原本と書き出しに保持できるが、本編へ決定できない。「この見た目には未対応の項目があります」と表示し、代替表示を完成品として確定しない。新しい外見データ版は「この版では編集に適用できません」と示し、元データを保って適用を止める。

## 10. 確認画面・決定・キャンセル

編集画面の「確認へ」で「確認中」へ移り、下書きを固定して全身・顔と変更一覧を示す。「髪型：変更前→変更後」のように名称で確認できる。費用なし、装備・進行維持を表示する。新しく選んだ項目が未制作・未対応・読込失敗なら、理由を示して決定を無効にする。「編集へ戻る」は下書きと履歴を保って編集へ戻る。

「この見た目に決定」を押すと「保存しています」と表示し、決定の連打を受け付けない。一度の確定保存が成功してから「見た目を保存しました」と表示し、ゲームへ反映する。変更のない再編集では「変更がありません」と示して閉じる経路を用意し、不要な保存を行わない。

未確定の変更がある時にキャンセルすると「編集した見た目を破棄しますか？」と確認する。「編集を続ける／破棄して戻る」を並べ、続ける方を既定にする。破棄の確認後に下書きと中断用の控えを消し、確定外見を維持する。変更がなければ、そのまま閉じる。初回は未保存のまま初回の選択入口へ、拠点での再編集は元の装備箱へ戻る。

## 11. 失敗と他の画面との競合

保存できなかった時は「保存できませんでした。編集内容は残っています」と伝え、「もう一度保存／編集へ戻る／レシピを書き出す」を提示する。保存失敗を理由に別人へ戻したり、確認前の下書きを捨てたりしない。

別タブなどで保存が進んでいた場合は「別の画面で保存内容が更新されました。最新の状態を確認してください」と表示する。最新の外見と編集中の外見を比較し、重なる変更を「最新の値を使う／編集中の値を使う」で確認する。重ならない外見変更は維持できる。確認後に改めて決定し、古い所持品や進行で保存全体を上書きしない。

競合を解決する間もレシピを書き出せる。新しい版の保存を読めない時は、未対応の領域を変換して確定しない。素材の読込みが止まった時も、ゲームへ反映済みとは表示しない。準備できた見た目を選ぶか、編集を続けるかを利用者が判断できるようにする。

## 12. 中断した下書きの復帰

操作が確定した後、編集中の値、固定、カテゴリの初期化基準Pを、本セーブとは別の中断用領域へ一時保管する。これはゲームの姿の確定ではない。保存できた時だけ「編集中の内容を一時保管しました」と表示する。一時保管に失敗した時は「一時保管できていません。閉じると変更が失われる可能性があります」と伝える。

再び開いた時に下書きがあれば、更新時刻と見本を示し、「途中の編集を続けますか？」から「続きから／破棄して始める」を選ぶ。破棄には確認を挟む。基準にした本セーブが更新されていた場合は、第11節の比較確認を経て再開する。

復帰では値と固定を戻すが、Undo／Redoの履歴は継承しない。復元した下書きを新しいUndoの起点とし、再開時の確定外見を新しい「編集開始時」の比較対象にする。「保存済みの見た目と比較しながら再開します」と案内する。下書きを復元しただけでゲームへ反映しない。

着信や他アプリへの切替から戻った時は、最後の確定した編集操作から続ける。保存中に中断した場合は、保存結果を読み直してから状態を示す。ブラウザやOSの強制終了直前の変更まで必ず残るとは保証しない。正常な決定または明示的な破棄の後は、中断用の控えを残して再提示しない。

## 13. 制作する順番

第1段階はAの再現、下書きと確定の分離、二つの入口、確認・キャンセル、失敗時の保持を作る。新しい保存項目がなくてもAの姿が変わらないことを先に確認する。

第2段階は実際の3Dプレビューと、校正した外見選択を接続する。肌・髪・顔・体型と5部位防具を調整し、端末ごとの配置、数値入力、比較、50操作の履歴を通す。未制作資産は利用可能一覧へ混ぜない。

第3段階は固定付きランダム、お気に入り6枠、外見レシピ、中断復帰、競合の比較を揃える。段階公開時は、使える機能と準備中の機能を画面と台帳で一致させる。最後にiPhone横・縦、iPad、PCで下記の利用シナリオを確認する。

## 14. 受入シナリオ

以下は実装後の合格条件であり、今回の達成報告ではない。

| 操作する場面 | 期待する結果 |
|---|---|
| 新規開始でAを選び、確認して決定 | 入力を強制されず開始でき、採用Aを再現する |
| 女性的な見本で筋肉質・短髪・深い肌色を選ぶ | 全選択肢を使え、能力差が付かない |
| 同じ人の髪・肌・体型を変更し、兜を着脱表示 | 顔と手、通常髪と兜用髪、衣服・防具が対応する |
| 数字・±・ドラッグで同じ値へ調整 | 同じ見た目となり、ドラッグ1回をUndo1回で戻せる |
| 顔と肌を固定してランダム、続いて手動変更 | 抽選で固定値を保ち、手動では変更できる |
| 51操作、Undo、Redo、新しい変更 | 最大50操作を戻せ、履歴単位を保って新しい枝へ切り替わる |
| P02→B03→体型カテゴリ初期値へ | P02のB02へ戻り、比較対象の編集開始値は不変 |
| お気に入りへ登録し、上書きを取消 | 下書きと既存枠を保ち、ゲームの姿は変わらない |
| 本編セーブの取込み・初期化・復元 | 外見専用のお気に入り6枠を自動削除しない |
| レシピを読込み、プレビューで中止または適用 | 中止では元の編集、適用では下書きだけが替わる |
| 未知の髪IDを含むレシピで肌だけ編集 | 元IDを保持して書き出せるが、未対応の新規項目がある間は本編へ決定できない |
| 既存の確定セーブの未知髪IDを残して肌だけ変更 | 元IDを保持し、対応済みの肌項目を保存できる |
| 決定時に保存失敗または別タブ更新 | 成功を偽らず、編集を保持し、最新の進行を上書きしない |
| 途中で縦横切替・着信・再読込み | 操作途中の値を確定せず、復帰方針どおり再開する |
| 初回／再編集で変更を破棄 | 初回入口／元の装備箱へ戻り、確定外見を維持。不要な下書きを再提示しない |

## 15. 引き継ぎと確認していないこと

本書はゲームコードと既存ファイルを変更しない追加の機能設計である。保存形式と状態遷移の詳細は別添の技術契約で扱う。外見のID・名称・数は既存カタログを参照し、画面見本から新しい番号を推測して増やさない。

守れなかった決まり：本書の追加ではなし。迷って決めたことは、カテゴリ初期値の基準を全体見本Pへ固定したこと、お気に入りを本編進行から独立させたこと、復帰時の履歴を空で再開すること。確かめていないことは、本物の3D表示、全組合せの適合、保存・復帰の実動作、実機の速度と押しやすさである。これらを確認した後に機能の完成として扱う。
