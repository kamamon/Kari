# 状態異常の個性化：設計と監査
## 原作から抽出した構造（攻略二次資料）
- https://mh.mtwildwood.net/ja/mhfu/monsters/nargacuga/ と https://mh.mtwildwood.net/ja/mhfu/monsters/tigrex/ : 状態ごとの初期耐性・減少・再発上昇・最大耐性、毒の総ダメージと拘束時間の区別。攻略本由来とされるデータ、原本全頁・内部実装未確認。
- https://w.atwiki.jp/mhp2g/pages/131.html : 蓄積、状態解除、増加、加算で減少タイマーをリセット。毒中の再蓄積などKariの現行との違いもある。今回は現行の制御競合契約を維持。
- https://w.atwiki.jp/mhp2g/pages/127.html : 効果時間と耐性を別々に比較。効かない種も区別。
原作の数値、名称、個体の直接対応は実装へ移さない。採用するのはデータの軸である。

## 現行問題
src/game/ailment.ts: 共通threshold100、growth/stunGrowthの指数増加。種別の耐性、上限、持続、減衰頻度、毒総量が無い。同じ毒武器がどの種でも同じ効き方になり、毒ダメージが最大HP比のため上級で自動増加する。現行は全種共通の状態異常で、武器・種の相性が弱点属性ほど出ない。
src/game/sim.ts の storeAilment と src/game/monster.ts の stepAilments に定義IDを渡すだけで、発症と時間経過に同一データを適用できる。entityIdで引かない。既存の整数蓄積とgraceを使い、別の状態機械を作らない。

## 新契約
threshold(n)=min(cap,initial+increase*n)*1000、正の命中が到達すれば発症し蓄積をリセット。immune=trueは新規蓄積しない（実装20種に完全免疫を割り当てない）。減衰は各状態の加算から decayIntervalTicks ごとに decayAmount を引き、0未満にしない。再発は個体ごと、同じ種の別個体へ伝播しない。状態異常の持続はKariの60Hz tick。毒は固定総ダメージを期間に配分、端数があっても最後に全量。初期20種の毒ダメージは級で変えない。上級の必要時間・技能倍率・毒バランスは今後の実測対象。現行の毒中の再蓄積禁止、睡眠初撃倍率、気絶は打撃頭部、grace、異常と罠/転倒の競合、終了イベント、瀕死での自然休眠は維持。免疫は定義可能だが、根拠のない完全無効を実装しない。訓練標的と未定義種は旧規則、ガルドロスの初回は従来基準を保存する。
毒の総量の配分は floor(elapsed*hits/duration) で、そのtickまでの必要回数を求める。定義時のduration/hitsを検証。旧900tick/10回では90tick間隔を維持。原作時間を再現したものではない。

## 受入
A03/A04/E05の狭い一部分。初回/2回目/上限、毒量、麻痺/睡眠/気絶の時間、競合猶予、同種2体、死亡・捕獲、休眠との競合を記録。実装種20×4状態のデータの欠落なし。未実装種へ外見だけから完全免疫を付けない。統合時は現行mainのテストに加え、新規Vitestを走らせる。
物理・属性補正・武器技能・弾瓶の変更は後続E05/E06。種ごとの罠相性、部位変化による耐性と級別上限、毒中再蓄積、異常の発症確率は別タスクとして設計する。今回の限定範囲をE05全体完了としない。
