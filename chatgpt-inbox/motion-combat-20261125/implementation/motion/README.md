## 確認した問題と変更

### 1. 断岳剣の薙ぎ払い

基点の `poses.ts` は tick 34 で spine yaw 30° + chest yaw 62°、骨盤の回転0°だった。骨盤の回転と踏み替えを加え、同じ時点の回転を骨盤44° + 背/胸48°へ分けた。膝で12cm沈み、接触へ向かって重心を前へ8cm移す。武器の正本の軌道・技の長さ・ヒット窓・controllerの移動曲線はそのままで、左右の手が柄へ届く上体を作る。

3攻撃の全811サンプル（1/4 tick刻み）を、本物の `HunterRig.setPose()` → `weaponToTrack()` → 左右socketの世界座標まで通して検査した。基点では薙ぎ払いの最大握り誤差約14.55cm、縦/抜刀斬りの回復中は約5.35cmだった。差し替え後は全サンプルで2mm以内（独立検査の最大値は浮動小数点の丸め誤差程度）。ひじの最大曲げ約149.28°、ひざ約92.04°。握りが届くことは確認したが、指・手のひらの向き、すべての自己貫通を合格にしたわけではない。

### 2. 足を滑らせない場面を明確にする

通常歩行では母指球を世界座標に保持する。実際に進んだ距離から周期を決めるので、壁へ押し続けても入力値だけで走り続けない。停止時に浮いている足は約0.16秒で下ろし、その場で大きく向きを変える時は片足ずつ踏み替える。納刀中の全7系統と断岳剣の通常歩行にも脚IKを使う。

急な90°/180°変更では、ゲームの位置は入力方向へすぐ進み、体のyawは数フレーム遅れて追う。ここで世界座標へ足を固定し続けると脚が伸び切る。そのため、移動方向と体のずれが約26°を超える、旋回が約149°/秒を超える、または足が届く範囲から離れる時は、80msの足上げを経て安全な歩行へ戻す。整ったら接地を再開する。**急旋回中の無滑走を保証する処理ではない。** 動画を見ながら方向別の踏み替えクリップへ交換する余地を残してある。

走りは接地率を0.60から0.32へ下げ、短い両足の空中局面を作る。足を過大に前後へ伸ばして速度を表現しない。

### 3. 靴のつま先が地面へ入る問題

現行モデルはつま先の骨を持たず、靴全体が剛体で動く。接地solverの母指球はz=0.13mだが、靴の先はz=0.19mまである。母指球を軸に踵を上げるだけでは、先が地面へ入る。

`groundLowerBody` はまず骨盤を解き、その骨盤位置を保持したまま、剛体の靴のつま先/踵/底の厚さに合う高さへ足を置いて膝を解き直す。これにより上体と武器の位置を変えずに補正する。断岳剣の3攻撃・811サンプルについて、足の骨へ重みのある実際の254頂点を `applyBoneTransform()` で変形し、地面下へ入らないことを確認した（最小yは約−1.9×10⁻¹⁰mの丸め誤差）。

この補正寸法は現在の仮モデルに固有である。正式GLBには、そのモデルの靴底の輪郭とtoe骨を使う。今回、6系統の全攻撃の剛体靴・防具の全組み合わせまでの頂点検査は行っていない。

### 4. モーションと判定の同期

`HunterAnimator` の短い遷移ブレンドを、攻撃の判定窓と弓の発射tickでは終える。6系統の正本の軌道に合わせた解をそのまま表示する。発射tickは `[shoot.tick, shoot.tick + 1)`。`view.ts` がIK後に骨の姿勢だけをもう一度混ぜる処理を外し、手と武器が離れる経路を止めた。

`run.tick` は「次に処理するtick」である。従来の描画関数は命中停止に入ると次のtickを表示する場合があった。プレイヤー専用の `playerRenderTick` で、命中停止の最後のstep（hitstop=0、advanced=false）まで処理済みの接触tickを保つ。溜めはholdTickの姿勢を保つ。simulationの時刻・攻撃・移動は変更しない。

### 5. 同じ脚の位相を繰り返し検査していた問題

以前の `solveState()` は毎回新しいAnimatorを作ってdt=1で一回進めていた。timeを変えても歩行位相が変わらず、既存の歩行テストの12/40サンプルは実際には同じ脚の位相だった。絶対時刻から位相を算出するように直した。元の47件の人間モーション検査は、この修正後も通過した。
