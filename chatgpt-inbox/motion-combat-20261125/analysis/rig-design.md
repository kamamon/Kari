# ハンターの骨格・モデル・動作設計

確認基点: `kamamon/Kari` / `main` / `1d8e084d0d16fe77c376570f9542dd3c54fb5332` / v0.20.0。確認日: 2026-11-25（日本時間）。

この文書は現状のソースを読んだ監査と、置き換えの設計である。**正式な人型 GLB・Blender ファイル・手付けアニメーションを完成させたという報告ではない。** この納品で用意したコードの適用範囲、実行した検証と結果は、同じ納品の README と検証結果を正本とする。以下で「提案」「目標」とした数値は今回の制作判断であり、人間の医学的な標準値、端末の実測値、既存ゲームからの転用ではない。

## 1. 結論と置き換える順番

自然さを改善する優先順は、①実際の移動量に足を合わせる、②攻撃の準備・加速・制動を全身で分担する、③状態遷移中も握りと接地を守る、④鎖骨・ねじり・つま先・指を持つ正式モデルへ移る、である。

現状にも 2 本骨の IK、踵の補正、足位置を決めた攻撃、関節範囲の検査がある。その土台は使える。骨を増やすだけでは、入力方向と歩行方向の食い違い、壁で止まった時の足踏み、攻撃途中の姿勢補間による手離れは直らない。先に現在の 17 関節で運動と接触の一貫性を整える。

また、攻撃を「自然に見せるため」に自由な見た目の補正だけで刃を大きく動かすと、判定と映像がずれる。**通常姿勢の表現、接触を守る補正、攻撃の判定軌道を別々に管理し、最後に一致を検査する。** 現行 6 系統では体の動作から判定軌道を再生成し、断岳剣では先にその方式へ移行するか、既存軌道を拘束として残すかを明示する。

### 2.1 具体的な問題と、既存検査の見落とし

1. **表示上の歩く速さと、実際の移動量が一致しない場合がある。** `player.ts` は入力方向へ移動を要求し、体の向きを徐々に追従させ、`p.moveSpeed` に要求した速さを入れる。壁で押し戻された時や旋回途中でも、足運びがその scalar speed だけから計算される。確認すべき値は `prevPos → pos` の実移動と身体ローカルの前後左右成分である。
2. **固定した足も身体と一緒に回ってしまう経路がある。** authored root に対する接地と、現実のゲーム内の接地は異なる。壁、旋回、ロックオンの向き変更、回避方向、エリア移動を含めて確認する。
3. **姿勢を解いた後で別の補間をかけると、手と武器の関係が崩れる。** `view.ts` は `applySolved()` の後に、切り替え途中なら補間した `pose` を `setPose()` し直す。武器・盾は解いた位置のままなので、腕だけ別の姿勢になる経路がある。
4. **補間中・自由移動中の表示と判定は、素のクリップ一致テストだけでは保証できない。** 現行テストの 2 mm は、主に `evalMotion → solveBody` と保存済み track の比較である。実際の `HunterAnimator.frame()`、runtime の後段補間、充填姿勢、freeMove の脚からの骨盤補正まで含める必要がある。
5. **断岳剣だけ、上体のひねりが強くなりやすい。** `hb_attack_side_01` の tick 34 は `spine` の yaw が +30°、`chest` が +62°、`pelvis` の yaw は 0。単純合計では約 92°を背中側だけで負担するキーになっている。実姿勢の相対 quaternion でも確認し、骨盤・足の踏み替えへ分配する。
6. **手首の検査名と、実際に検査しているものを分ける。** 現在は「前腕の方向と武器軸のなす角」の検査であり、掌の回内外、手首の屈曲、指の接触を測っているわけではない。
7. **重心と足滑りの合格を、物理的な自然さの証明にしない。** 現在の重心は骨盤 60% + 胸 40% の近似で、腕・武器の質量はない。接地滑りの既存許容は 0.006 m/tick で、連続すれば大きなずれにもなり得る。接地一回の累積変位も別に調べる。

これはソースから確認できる経路とリスクであり、すべての技・端末で同じ見た目の不具合を再現した、という意味ではない。

## 3. 骨格設計

### 3.1 現在の単位・向き・寸法を固定する

ゲーム空間は m、Y 上、+Z 前、右手側 -X。原点は接地面の中央。simulation の actor が位置と向きを所有し、骨盤は actor に対する体重移動を表す。root と pelvis に同じ前進を重ねて入れない。

| 指標 | 現行 `REST` | 今回の方針 |
| --- | ---: | --- |
| 身長の基準 | 1.75 m | 維持 |
| 骨盤高 | 0.92 m | 維持し、構えで上下する |
| 肩関節間 | 0.37 m | 初期置き換えでは維持 |
| 上腕 / 前腕 | 0.29 / 0.27 m | 伸縮で帳尻を合わせない |
| 大腿 / 下腿 | 0.43 / 0.41 m | 足が届かなければ腰・踏み幅を調整 |
| 手の握り点 | 手首より先に 0.04 m | 手首の向きを変える時は握り点の移動も解き直す |

頭身は別の造形判断として扱う。設定図メモは約 8.5 頭身と説明する一方、`HEAD_SHAPE` のあご〜頭頂本体は約 0.1855 m で、髪束を除いた単純な 1.75 m 換算では約 9.4 個分になる。これを人体平均と比較して即修正せず、4 方向の原画・実モデルを同縮尺で並べる。人間らしい比率へ改訂する場合の**制作案**は頭高約 0.22〜0.23 m、約 7.6〜8.0 頭身だが、兜・首・肩・防具の整合も同時に直す。今回のモーション修正に紛れて外見を変えない。

出典: [hunterBody.ts](https://github.com/kamamon/Kari/blob/1d8e084d0d16fe77c376570f9542dd3c54fb5332/src/render/hunterBody.ts)、[基準ハンター設定図メモ](https://github.com/kamamon/Kari/blob/1d8e084d0d16fe77c376570f9542dd3c54fb5332/art-source/player/hunter_base_turnaround_v1.md)。

### 3.2 まず 17 関節を使う。その後に補助骨を足す

| 系統 | 現行の主要骨 | 正式モデルでの追加案 | 役割 |
| --- | --- | --- | --- |
| 中心 | pelvis → spine → chest → neck → head | 原則として主要名を維持 | 骨盤・胸・顔の向きを分担 |
| 腕・左右 | chest → upperArm → forearm → hand | clavicle、upperArmTwist、forearmTwist を各側 | 肩の上げ下げ、前腕の回内外、ねじり潰れ防止 |
| 脚・左右 | pelvis → thigh → shin → foot | thighTwist、shinTwist、toe を各側 | 大腿のねじり、蹴り出し、母指球を軸とした踏み替え |
| 手指・左右 | なし | 1 指 3 骨 × 5 指 × 2 手 | 柄を包む形、弦の指離し、道具の把持 |
| 布・小物 | 現在は胸・腰・四肢へ重み付け | 外套左右、腰布左右の最大 4 骨を別枠 | 動作の後に少し遅れて追従 |
| 非変形ノード | root、4 socket | 名前と握り規格を維持 | 位置・武器・盾・納刀位置の接続 |

骨数の案は、最小拡張 25 本（17 + 鎖骨 2 + つま先 2 + 腕の twist 4）、脚の twist まで 29 本、指まで 59 本、布を足して最大 63 本の変形骨。root と 4 socket はこの本数に含めない。これは mobile 向けの制作目標であり、既にこの骨格に置き換わったという意味ではない。

**骨名を保つだけでは互換にならない。** 鎖骨を挟んで親子関係を変えると、既存上腕のローカル回転をそのまま再生できない。新リグは `rigVersion: 2` として、元の 17 関節のワールド姿勢から新しい親座標系へ変換する adapter を用意する。rest pose と inverse bind matrix を同時に確定し、武器 socket のワールド位置・向きが旧リグと一致することを検査してから移行する。

## 4. 関節、握り、接地をどう解くか

### 4.1 人間らしさは「止める関節」と「動く順序」で作る

攻撃は支持足・骨盤・胸・肩・肘・手・武器の順で力を伝え、終わりは逆向きに減速を分担する。全関節を同時に開始・同時に停止させない。ただし 3 tick の先行、5 tick の遅延などを全技に固定で足すと、短い技では攻撃窓が壊れる。**各技の既存 startup の範囲内で**、溜める点、加速する点、接触を狙う点、制動する点を決める。

以下は制作時の通常域の案。既存 `humanLimits.ts` の上限は別の破綻検知ゲートとして残し、足りないから上限を広げるという直し方をしない。

| 部位 | 通常制作域の目安 | 動かし方 |
| --- | --- | --- |
| 骨盤〜胸の合計 yaw | 通常 ±30°、大振りでも概ね ±45°までを狙う | それ以上は骨盤回転・踏み替えを先に増やす |
| 肘 | 通常 15〜135°程度 | 伸び切りを常用せず、方向を変える余地を残す |
| 膝 | 待機は軽く曲げ、歩行・攻撃では 5〜100°程度、深いしゃがみは別動作 | 膝の曲がる面を足先と大きくねじらない |
| 首 | 視線は先行するが、胸とのズレは普段 ±45°程度を狙う | 大きな振り向きは胸・骨盤が追う |
| 手首 | 屈伸・横曲げを小さく保ち、柄の方向変更は前腕・肘から分担 | 前腕と武器の角度だけで合否を決めない |

関節制限は完成モデルのローカル軸を定義してから実装する。Euler の各成分に単純な clamp を掛けるのではなく、回転軸の swing と twist を分け、前腕ねじりを補助骨へ分散する。小さな超過の修正では、手を武器から離すのではなく、肘 pole・肩・胸・足の順で姿勢を解き直す。

### 4.2 握りは位置と向きの両方を拘束する

武器側に主手の握り transform、添え手の握り transform、刃の基点・先端を定義する。主手と添え手のどちらも、手のひらの向きまで含めて拘束する。弓は左手が本体、右手は弦のノック点、盾は前腕の固定点、双剣は左右別の武器として扱う。

現状の solver は肘から「手首 + 0.04 m」までをまとめて解いている。ここへ hand 回転だけを追加すると、実際の socket が 0.04 m の円弧を動き、逆に握りずれを増やす。手の向きを `R_hand`、手首から握り点への局所ベクトルを `p_grip`、武器の握り位置を `G` とすると、まず `W = G − R_hand × p_grip` を手首目標にし、その W へ上腕・前腕の IK を解く。最後に palm のワールド向きから親前腕の回転を除いて hand の局所回転を決める。

指は手首 IK の代わりに使わない。通常の握り、抜刀、持ち替え、弓を引く指、離す指の少数の hand pose を用意し、on / grab と同期する。添え手を柄の上で滑らせる技では、手が外れた区間と接触する区間を明記する。

### 4.3 足の固定は、接触点をワールド座標で持つ

足首を固定すると踵上げの時に不自然になる。heel / sole / ball / airborne の接触状態を持ち、踵接地 → 足裏 → 母指球 → 離地を区別する。

各足に「固定した接触点のワールド座標」「接地面の法線」「固定時の actor transform」「接触の重み」を保存する。描画前に現在の actor の逆 transform で局所座標へ戻し、2 本骨 IK を解く。向きを変える時も固定点が地面を滑らない。足が届く範囲を越えそうなら、骨盤を少量下げるか固定を解除して踏み替える。骨を伸ばす、地面の下へ足を逃がす、といった補正をしない。

初期版の平地に対する受け入れ目標は、固定中の接触点の累積ずれ 2 cm 以下、単フレーム 5 mm 以下、足裏の地面への沈み 1 cm 以下。これらは提案する見た目の QA 値で、現在すべて達成済みという意味ではない。急旋回・回避・段差・押し戻しは別ケースとする。

攻撃の移動曲線が壁で止められた時、見た目だけで予定位置まで進めない。予定 root と実 root の残差は足の補正に使い、刃の判定は実際の actor transform に従う。大きな残差は踏み直しとして見せる。将来の傾斜地では、地面の法線と足の向きを合わせつつ、膝・骨盤の許容域を優先する。

## 5. 状態と補正の優先順位

1. **simulation** が行動、tick、移動、向き、溜め、ヒットストップ、当たり判定を確定する。
2. locomotion / weapon stance / action / hurt / dead から主姿勢を一つ選ぶ。全身の強い被弾・死亡は攻撃に優先する。
3. 前の状態との遷移を、制御値または quaternion ベースで行う。単純な Euler の成分補間で 179°→−179°を遠回りさせない。
4. 視線、呼吸、傾きの微調整を加える。ただし攻撃窓中の武器軌道を変える骨には無制限に加算しない。
5. 足の固定 → 骨盤の到達補正 → 胸・肩 → 両腕の握り IK → 掌の向きの順で、最終姿勢を解く。
6. 武器・盾・弦・指をその最終姿勢に配置する。ここで姿勢だけを再補間しない。
7. 必要な布・髪・小物の追従を最後に加える。攻撃判定の入力に使わない。
8. 描画後ではなく、この最終姿勢と同時刻の track の誤差を測る。

攻撃開始から最初の当たり判定までに姿勢の大きな遷移を収束させる。攻撃窓中に crossfade の重みが残る場合は、刃の位置・向きを基準へ拘束する。早い技を長いブレンドで鈍らせない。歩行停止も、両足をその場で同時に初期位置へ戻すのでなく、支持足を残してもう片足を揃える。

Three.js の AnimationAction は weight、time、crossFade などを提供するが、Kari の 60 Hz の攻撃窓を代わりに管理しない。正式クリップ統合でも行動 tick が時刻の正本であり、`warp=true` による自動再生速度変更を戦闘クリップへ無条件に使わない。[Three.js AnimationAction](https://threejs.org/docs/pages/AnimationAction.html)

## 6. 7 系統のモーション案

既存の行動 ID、当たり窓、キャンセル窓を出発点にする。ここでの内容は演技・体重移動の提案であり、別添の差し替えコードがこれら全部を手付けクリップとして実装した、という意味ではない。攻撃力の全技数値は同納品のバランス表にまとめる。

### 6.1 断岳剣: 持ち上げる重さと、止める重さ

- **縦斬り**: 後足へ乗せ、膝を軽く抜いて骨盤から剣を持ち上げる。頭上の溜めで肘を完全に伸ばさない。前足を先に置き、骨盤が前へ移り、胸と腕が後から刃を落とす。接触後は刃先を急停止させず、腰と前膝で減速する。
- **横薙ぎ**: 背中だけを 90°近くねじる現在のキーを、骨盤・後足の回旋と踏み替えへ分配する。刃の通過後に頭と胸を先に戻し、腕は少し遅れて構えへ戻る。
- **抜刀斬り**: 背中から刃が身体を通らずに抜ける経路を確保し、握りを取る → 刃が離れる → 両手になる → 打点へ進む、の順を見せる。
- **溜め**: 溜めるほど腕を大きく振動させるのでなく、支持足・息・肘の張りで力を表す。ヒットストップで刃が止まった時、足だけ歩き続けない。

現行縦斬りの時間は 0〜21 tick が準備、22〜29 が判定、30〜71 が後隙、18 tick で溜め保持。例えば準備の中を「0〜9 重心を後ろへ、10〜17 振り上げ、18 保持、19〜21 踏み込みの確定」と再配置できる。これは既存攻撃窓を変えずに行う演技案。

### 6.2 護刃: 盾と身体を近く保ち、三段目で伸ばす

- 1 段目は肘を体の近くに保つ小さい斜め斬り。前足の短い踏み込みで距離を作る。
- 2 段目は反対側へ返し、腰も小さく戻す。1 段目終了時の姿勢から始め、いったん待機へ戻らない。
- 3 段目の突きは後足で押し、胸と肘が前へ伸びる。盾側は防御を残す。高い攻撃力はこの狭い打点と、突き切った後の復帰を伴う。
- 盾打ちは肘だけのパンチにせず、前腕に固定された盾へ肩と体重を乗せる。打撃の見た目が鋭くても、スタンの有用性を含めて火力を決める。

### 6.3 長尖槍: 長い射程と、狭い打点を両立させる

- 通常三連突きは同じポーズの繰り返しにせず、1 段目は腕、2 段目は後足の送り、3 段目は前足をもう一度確定して深く突く。
- 盾の位置と正面を毎回崩しすぎない。刺した後に柄を引く時間を残し、次の突きが伸ばし切った肘から始まらないようにする。
- 上段突きは腕だけで真上へ上げず、胸の向きと前足の距離で打点を高くする。
- 防御突きは足を狭く動かす安全な技。高火力にしすぎない。カウンター成功は盾・後膝で衝撃を受けてから刺し返し、通常突きより強い一発を視覚的にも説明する。
- 突進抜刀は長い槍が地面・自分の脚を通らないことを背面視点でも見る。

### 6.4 大槌: 頭の重さを両手・腰・足で支える

- 叩きつけは手の高さだけを変えず、重い頭が外へ落ちるのを、添え手と腰で導く。支持足を先に置く。
- 横振りは後足の母指球を軸に回り、槌頭を身体の後ろへ通した後に勝手に止めない。接触後の減速を反対足で受ける。
- 溜め叩きは重心を低くして準備し、放す直前に骨盤が上がり、打点へ下がる。長い隙には見合う高打撃とスタンの設計を与える。
- 現行通常技は smash ↔ swing の相互派生であり、決まった三段終端がない。「最終段ボーナス」を全ての swing に無条件に付けるのでなく、強打を溜めの役割に置くか、将来コンボ履歴付きの終端を新設する。

### 6.5 双剣: 手数より先に左右の役割を読む

- 1 段目右、2 段目左で、骨盤と肩の小さな反転を使う。毎回両腕を同時に最大まで開かない。
- 交差斬りは左右の刃が同じ場所へ入る直前に、肘が互いにぶつからない高低差を付ける。左右別の判定を保つ。
- 連続突きは左右の手を入れ替え、反対側の足を支えとして前へ出す。
- 乱舞は前半で細かく刻み、最後の両刃で踏み込みと上体の解放を大きくする。高い最終段ダメージは両刃の**合計**として評価し、各刃へ同じ合計値を重複設定しない。
- 強化状態の速度上昇でも足・体重移動を同時に速める。腕だけが回り、脚が元の時間に残る動きにしない。

### 6.6 太刀: 弧の連続性と、下がる時の足順

- 袈裟 → 斬り上げ → 突きは、前の切っ先の終点から次の始点へつなぐ。刀を毎回構えへ戻すと、長い刀が軽く見える。
- 突き終端は前膝と後足で長さを出す。身体を前へ折りすぎず、刺した後に足から戻る。
- 下がり斬りは既存の後退 2 m を尊重し、後ろ足が先に逃げ、前足が追う。刃は敵側を向き、身体だけが後ろへ滑る見せ方を避ける。
- 兜割り系の強打は準備で刀・胸・前足の向きが読めることを重視し、狭い打点に高い攻撃力を割り当てる。身体が宙へ飛ぶような新演出は、実際の移動曲線や地面との関係を決めてから足す。

### 6.7 環弓: 肩を支え、引き手を離す

- 左手で弓を支え、左右の肩を水平に近づけて右肘を引く。右手だけが弦を伸ばす動きにしない。
- 引き絞り終端では引き手を頬の近くに寄せる制作目標を設ける。正式頭モデル・弦の位置に対して照合し、顔を貫通させない。
- 放つ瞬間は右手が後ろへ少し抜け、左手・弓の反動は小さくする。矢の生成時刻と指離し・弦戻りを同じ tick にする。
- 散射は各矢の係数を合計して近距離の報酬を評価する。溜め射ちは高い一発と引き時間・スタミナ・照準難度を一緒に評価する。
- 現行 `shot` は `active=[14,18)` に対し矢の生成が tick18、`spread` は `active=[12,16)` に対し生成が tick16。位相名の境界と実発射がずれている。発射を早めるのでなく、正本の `shoot.tick` を保って位相表記を合わせるのが初期修正案。

## 7. 攻撃力と動作の接点

当てにくさは「見た目が大きい」だけで決めない。発生までの時間、旋回を止める時刻、判定の幅・高さ、判定の持続、前進量、外した時のキャンセル可能時刻、防御・移動の安全性、コンボをそこまで続ける必要性から判定する。

弱い連打だけでも遊べる入口を残し、敵の隙を読んで強い終端まで続けた時に効率が上がる構成を狙う。安全な盾突き・長射程の連打・短い回避派生へ、単に「狙いが細い」という理由だけで最大火力を与えない。逆に乱舞は総ヒットの合計、弓は複数矢と距離補正、溜めは追加保持時間込みで比較する。

最終段の大きい音・刃の軌跡・身体の制動は、最終段のダメージ発生に合わせる。空振り時に命中演出を出さない。ヒットストップは命中時だけの演出として、係数を上げた分だけ長くし続けると操作のテンポが崩れるため、ダメージと別の上限を持つ。

また、コンボ終端の報酬は、前段を省略できる入口を含めて調べる。技が単独ボタンでも直接出せるなら、その技名だけに「三段目」の倍率を付けてもコンボの報酬にはならない。現在の実際の派生グラフ・状態条件を正本にする。

## 8. 正式モデルのメッシュ設計

Three.js の SkinnedMesh は骨格だけでなく、頂点ごとの骨 index と weight を使って変形する。骨を増やした場合は同じ頂点を旧 weight のまま残さず、肩・肘・股関節・膝・手首の変形を再調整する。[Three.js SkinnedMesh](https://threejs.org/docs/pages/SkinnedMesh.html)

| 部分 | 制作要求 | 受け入れ姿勢 |
| --- | --- | --- |
| 肩・脇 | 胸から上腕へ流れる面。鎖骨の持ち上げに追従し、腕を上げても肩が凹まない | 弓の引き絞り、剣の頭上溜め、背への抜刀 |
| 肘・膝 | 曲がる中心とその前後へ必要な面を置く。曲げの内側を折り畳み、外側の体積を保つ | 90°曲げ、深いしゃがみ、回避の丸まり |
| 前腕・手首 | twist の重みを腕に沿って配分し、細い手首だけへねじりを集中させない | 刃の返し、槍の上段、両手持ち |
| 手 | 柄の太さに合う掌と指。親指を閉じた固定形だけにしない | 大槌、太刀、弓の指離し、道具を飲む |
| 股関節 | 脚を前後に出しても腰布と身体が裂けず、臀部の体積が消えない | 大股、後退、片膝 |
| 足 | 踵・足裏・母指球・つま先の形が判別できる | 立位、蹴り出し、旋回、着地 |
| 防具 | 装甲板は硬さを保ち、革や布は適度に追従。装備で隠れる身体を同時に隠す | 最大腕上げ、深いしゃがみ、回避 |

制作時の bind pose は腕をやや開いた A ポーズを案とするが、現行の「気をつけ」rest pose を黙って差し替えない。採用する bind pose、骨の局所軸、主要骨の名称、socket transform、inverse bind matrix を一組としてバージョン管理する。glTF の skin は joint と inverse bind matrix を定義するため、座標変換とバインドを二重適用しない。[Khronos glTF 2.0 仕様](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

見た目の目標として、ハンター本体と標準装備の LOD0 を合計 1.2〜2.0 万三角形、通常 LOD を 0.6〜1.0 万三角形、skin weight は 1 頂点最大 4、素材を少数 atlas にまとめる案を置く。**この数値なら iPhone で動くと保証するものではない。** モンスター、草、透明な効果、影を含む戦闘全体で測り、必要なら下げる。

## 9. Blender → GLB → ゲームの制作経路

1. 現行 1.75 m の参照体・武器寸法・主要 socket を Blender へ置き、同じ大きさで作る。
2. 編集用の IK・足の固定・pole・手の握りコントロールと、書き出す変形骨を分ける。
3. 技ごとの時刻表を取り込み、60 tick/秒との対応を固定する。原画や動画だけを完成アニメーションとして登録しない。
4. 制御リグで演技を作り、変形骨へ bake する。制約やドライバの実行をゲームに持ち込まない。glTF の出力対象に合う骨の transform アニメーションへする。
5. clip 名は行動データと完全一致させる。Action / NLA の関連付けを確認し、未関連の Action が出力されない事故を防ぐ。Blender の export mode で挙動が異なるので、使用した Blender 版と export preset を保存する。[Blender glTF マニュアル](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html)
6. 出力後は GLB を読み戻し、clip 本数、名前、長さ、骨、socket、skin、向き、大きさを検査する。Blender 内で動くことを出力後の保証にしない。
7. 体を正本にする技は、この最終クリップの weapon socket と blade marker から track を生成する。現在の手続き生成と別々の曲線を手作業で維持しない。
8. 素材ビューアで 4 方向、通常速、0.25 倍速、1 tick 送りを確認し、その後ゲーム側で行動 tick に同期して再生する。
9. runtime の root motion は simulation が実行する。クリップの root 水平移動は in-place で持ち、authoring 時の移動量は controller 用曲線として分離する。
10. 問題が出た時に戻せるよう、手続きリグと GLB リグは rigVersion で切り替えられる状態から始める。採用後に不要な経路を整理する。

### clip の契約に足す項目案

既存の JSON を壊さない別 manifest として、`rigVersion`、`durationTicks`、`sourceActionId`、`contactLeft/Right`、`primaryGrip`、`secondaryGrip`、`authoringRootCurveId`、`trackHash`、`sourceAssetHash` を持つ。接触窓や握り点は visual contract であり、無敵・防御・攻撃力の判定を二重に定義しない。

## 10. 実際の受け入れ検査

### 自動検査で見るもの

- 保存された技単体の全 tick に加え、前段→次段、歩行→攻撃、被弾→待機、回避→攻撃を実際の animator 経路で流す。
- 30 / 60 / 120 fps と変動 dt で、同じ simulation tick の刃の位置・向き・手の到達を比較する。hitstop 中や charge 保持中に脚だけ進んでいないか調べる。
- 腕の到達は現行上限を保ち、正式モデルでは掌の方向誤差も測る。武器先端の位置誤差は柄の 2 mm とは別に測る。向きベクトル誤差を m と呼ばない。
- 足の変位は actor ローカルだけでなくワールドで測る。接地中の累積ずれ、壁で停止、90°・180°旋回、後退、斜め移動を含む。
- 槍・両刃・盾・弓は、主手の 1 本だけでなく副手側も検査する。
- 断岳剣・回避・被弾の経路も対象へ加える。ただし新しい validator を通すために限界値だけを緩めない。
- clip と action の時間、shoot / hitWindows と phase の境界、animation event と実ダメージの時刻を照合する。

### 人が見るもの

訓練場の白床・足元グリッド・正面 / 真横 / 背面 / 実戦カメラで比較する。止めた 1 枚では、力の流れや足滑りを判断できない。最初は通常速で「重い武器の始動と停止が見える」「最終段だけ見ても強さが読める」「攻撃した手が離れない」を確認し、その後低速で原因を探す。

iPhone 実機では、通常装備と最も大きな防具、単体の大型戦と群れのいる戦闘、草と効果が重なる場面を各 60 秒以上計測する案とする。平均 fps だけでなく frame interval p95 と 100 ms 超の回数を残し、旧版と同じ設定・シナリオで比較する。モーション評価の目標は、CPU 時間の小さい増加に抑え、GPU の draw call や透明処理を無関係に増やさないこと。数値は計測後に決める。

## 11. Claude への引き継ぎ

このレビューを受けて最初に行う順番は、runtime の実移動を使う歩行と遷移の修正 → 現行 7 系統の攻撃力表の適用 → 最終描画姿勢と track の照合 → 断岳剣の足と骨盤の再設計 → 正式 GLB の制作、がよい。

差し替え用ファイルは、同納品の README の適用手順に従って受け入れる。`weaponClipSpecs.ts` と tracks の原生成器 `tools/gen-weapons.mjs` を別々に直してはならない。生成器を修正した場合は再生成差分と再生成再現性まで確認する。

**守れなかった決まり:** このレビュー単体では正式モデル・正式 clip は作っていない。ゲーム上で全提案を実装完了と扱えない。

**迷って決めたこと:** 現在の 17 関節を使う修正を先行し、鎖骨・指・布を含む 59〜63 骨への移行は別段階にした。頭身は原画・防具の整合が必要なので即変更しない。

**確かめていないこと:** iPhone 実機の見た目・性能、全技の新しい手付け演技、正式 GLB の読み込み、布の追従、傾斜地、人体計測に基づく厳密な関節域。ここでの技術レビューはソースと公式仕様の確認であり、実際のプレイ評価の代わりにはならない。
