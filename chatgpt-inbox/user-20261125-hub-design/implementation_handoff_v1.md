設計日・提出再確認日：2026-11-25 JST。**この提出物は設計・原画・制作資料です。新しい拠点は未実装です。**

この文書は、完成済み `Kari_Hub_Design_v1.pdf`（主に13〜16頁）から再構成しました。失われた旧Markdownと同一バイトではありません。PDFの参照版はv0.22.0、提出時の最新監査はv0.26.0です。[最新状態の追補](latest_state_addendum_v026.md)を併読してください。

## 1. 採用する場合の基本方針

灯継ぎの里を、水辺−10m、工房−3m、広場0m、住居+8m、展望+22mの五段へ拡張する。歩ける床の高低差32m、外形120×110mは初期試作の提案値。既存ゲームの実測値や実装済み地形ではない。

常用4施設は中段周辺へまとめる。依頼板・商店・装備箱は0m、工房は隣接する−3mへ置き、通常の受注は中段で完結させる。散策経路を通ると、水辺、住居、展望へ到達し、別の経路で里の中心へ戻れるようにする。

ChatGPTの変更は本inboxの制作資料のみ。ゲームコード、公開データ、採用原画への取り込み、検証、公開は[AGENTS.mdの分担](https://github.com/kamamon/Kari/blob/1e078bfce1e68f287ae577cf41d2fe5bafb94afa/AGENTS.md)に従い、Claude側の通常手順で行う。

## 3. 推奨する実装順序

### P0 — 中段の地形と視点を試す

依頼板・商店・装備箱を0m、工房を−3mへ仮配置し、階段と踊り場、上下の見通しを作る。NPCを担当施設と一緒に配置し、床高、影、当たりも揃える。4施設への到達、接地、カメラ、施設判定、「一覧」、保存互換を優先して確認する。

主経路幅3.5〜4.0m、階段幅2.5〜3.0m、踊り場幅4.5m以上を試作値とする。階段の蹴上げ0.15〜0.18m、踏面0.28〜0.32mを見た目の目安にしつつ、実際の歩行面と接地を検証する。3m差を8〜10%の荷車坂でつなぐなら水平延長約30〜37.5mを確保する。概念図の短い線をそのまま急斜面へ置き換えない。

### P1 — 五段と二つの道、生活の外観

全五段と二つの回遊路を接続する。初期は、歩行床が同じXZで重ならない構成にする。宿・集会所・水車・荷揚げ設備の外観、数人の短い仕事、局所音、水と煙を追加する。橋は下を通行しない構成から試せる。

配置と視界が安定してから、石段、梁、柵、擁壁、灯具などを繰り返し使える制作単位へまとめる。原画の背景人物を既存NPCの代用にしない。

### P2 — 室内・夕景・複層の拡張

宿と集会所の内部、昼夜・天候、進行に伴う小物や修繕の変化を追加する。橋の上と下を歩く構造は、複数の床を選べる仕組みと床・天井・当たり・カメラの対応後に導入する。

乗用昇降機は必要性を確認してから検討し、準備の必須経路にはしない。時間帯による主要施設の閉鎖や現実時間待機を追加しない。段階は制作順序の推奨であり、日程・工数・性能達成を約束するものではない。

## 4. 高さのために必要な技術対応

v0.22.0のPDF監査に対し、v0.26.0でも地形とカメラの基本的な課題は残る。最新コードに基づく補足は[追補](latest_state_addendum_v026.md)を参照する。

| 現在の仕組み・制約 | 必要な対応案 | 実装後に確認すること |
| --- | --- | --- |
| `groundHeight(x,z)`は最大高を0から計算 | 全高に+10mを加えるか、負の床高を扱える計算へ拡張 | −10m・−3mの床が0mのままにならない |
| 同じXZでは最高のplatformだけを床として扱う | 初期は歩行床のXZ重複を避ける。多層化では床・層を選ぶ仕組みを設ける | 橋の下から上へ吸着せず、床を突き抜けない |
| platformは水平な四角、`stepUp = 0.35` | 連続斜面または適切な小段差と安定した接地 | 足の浮き、階段への引っ掛かり、急な高さ変化がない |
| 施設の接近判定はXZ距離が中心 | 施設の床・層・高さ許容を接近条件へ加える | 上階から下階の工房などを開かない |
| 建物は`y=0`、案内輪は`y=0.03`固定 | 建物、輪、入口、当たりの高さ範囲と輪郭を床に揃える | 輪の浮き・埋没、入口や庇の柱への引っ掛かりがない |
| NPC本体は`y=0`、影は`y=0.02`固定 | NPC、影、当たりを担当施設の床へ合わせる | NPCが浮かず、段違いの当たりが歩行を妨げない |
| 当たりはXZ中心、カメラも0基準の円柱高さを参照 | 床、天井、柱、手すり、上層建物の高さを区別 | 軒下、橋下、階段折り返しで視点が大きく跳ねない |

既存の`validateHub`にはNPCと当たりの対応、施設前やspawnとの離隔チェックもある。施設・NPCを動かす場合、配置データと検査を一緒に見直す。見た目の高さだけで移設完了とは扱わない。

### 床高を+10mずらす場合

| 設計の相対床高 | 実装座標の例 |
| ---: | ---: |
| −10m | 0m |
| −3m | 7m |
| 0m | 10m |
| +8m | 18m |
| +22m | 32m |

建物、施設、NPC、影、スポーン、カメラも同じ変換へ揃える。オフセットは負の床高への対処候補であり、坂、複数階、施設判定、当たり、カメラの課題を単独で解決しない。高さをJSONへ足すだけで複層地形の実装を完了扱いにしない。

## 5. 描画と実機確認の方針

- 五段と視界ごとに景観を分け、遠い家は室内を持たない外観にする。
- 階段、梁、柵、擁壁、灯具を共通部材として組む。
- 遠景の窓明かりは素材による表現を中心にし、多数の実ライトを同時に置かない。
- 水、霧、透明な布、煙の重なりを抑える。
- 近い住民の仕事を優先し、遠い動きの更新頻度を調整できるようにする。

実機性能は未計測。既存の検証画面で描画間隔の平均・p95・100ms超の回数を比較する。入口の見え方、上下への視線、字幕、タッチ旋回をiPhone/iPadで確認する。資料には新たな性能達成値を設定していない。

## 6. 受入条件

| 対象 | 実装後に確認する状態 |
| --- | --- |
| 高低差 | 中段から上下の生活域が見え、上層から通った広場を見下ろせる |
| 到達性 | 常用4施設と各段へジャンプなしで往復できる |
| 階の誤認 | 別階の施設を利用できず、橋へ不意に吸着しない |
| カメラ | 階段・庇・柵・橋で大きく跳ねず、主人公が見える |
| 日常と保存 | 「一覧」、装備変更、強化、売買、報酬、会話、支給、D09を維持し、既存保存を引き継げる |
| NPCと暮らし | NPC・影・当たりが床に揃い、通路と窓口を塞がず、場所ごとの仕事が伝わる |
| 実機 | iPhone/iPadで操作・視認性・描画間隔を比較し、結果を記録できる |

原画に橋があること、橋を渡れること、橋の上下を歩けることは別々に確認する。未実施の項目を合格扱いにしない。

## 7. 確認済み・未確認・判断を残した点

完成済みPDFには、既存仕様とコードの参照監査、採用基準画と原画の目視、画像寸法の測定を行った記録がある。最新v0.26.0の追補はコード・資料の読み取り監査である。これらは新地形の起動や試遊の代わりにはならない。

新地形のプレイ、施設接続、生活動作、昼夜、橋上下、室内、実機性能、建物四方向の整合は未確認。実装時のコード検証結果、依存関係のインストール結果、リポジトリへの提出状態は、今回のREADMEに記録する。

迷って決めた点は、常用施設を中段周辺に置き、32mの高低差を散策と眺望で強く見せること。通常の受付は中段に残し、最高段を調査、物語、展望の場所として提案した。

原画間の細部差、商店の縞布と生成り布の最終統一、建物の四方向、物語・音楽・納品設計との接続は採用時に調整する。元のMarkdownと同一バイトでの復旧は行えていないため、完成済みPDFから再構成した旨を冒頭に明記した。
