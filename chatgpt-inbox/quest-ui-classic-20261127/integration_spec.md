# 実装仕様：Kariオリジナルの2G型クエスト選択

## UIの骨格

```text
[里・初級受付] → [難易度を選ぶ] → [★1の依頼リスト]
      │                  │                    │
      │                  │ ← 戻る             │
      │                  └─ ★2 など          ├─ 行選択（右側に依頼書）
      │                                       └─ 受注する → 確認 → 開始
      └─ ほかの受付：中級★3/4、上級★5/6、極級★7/8
```

### A. 受付を開いた直後

- `facilityId`から受付の`questRankId`を取得する。既存`receptionRank()`を再利用。
- 上部にその級の名前、中央に**縦並びの★1／★2などの大きな選択肢**だけを出す（4受付の場所は今のまま）。
- 級に存在しない星は表示しない。星に0件の依頼があれば、原則「0件」と出して詳細には入らせない。未解放の仕事も件数には含める。
- 左は選択メニュー、右は「星を選んでください」という短い案内。説明文・在庫・物語・図鑑はここへ流し込まない。
- 初級の補助「図鑑・物語・訓練場」は受付の独立した小メニューに移す。依頼リスト中には展開させない。

### B. 星を選んだ後

- 星を確定したら、**その星だけの縦一覧**に切り替える（現在の横並び星タブを使わない）。
- 1行40〜48px程度。左に小アイコン（40×32px程度）、中央にクエスト名、右に解放・達成状態。長い目的文は省略か小文字1行。
- 一覧の項目を上下キー／パッドの上下／指で選ぶと、右側の依頼書の概要を更新する。**選ぶだけで出発しない。**
- 一覧をタップ／決定すると選択が確定し、詳細領域の「受注」を操作できる。直ちに狩場へ飛ばさない。
- 同じ星の最終選択行、スクロール位置を保持。戻ると星選択へ。再訪時はその受付の前回選択星を復元してもよいが、別の受付の履歴とは混ぜない。
- リストの下へ説明文、素材・報酬全文、図鑑などを縦につなげない。

### C. 依頼書の情報

Kariに既にあるデータを使う。原作の画像や固有文面は使わない。

- 依頼名（目立つ見出し）
- 種類（狩猟／討伐／採集／採掘／現地納品／里納品）
- 対象モンスターの**既存図鑑縮小画像**と名前・頭数。混成群れは全種を別々に表示する。
- 目標・指定地・制限時間・クリア目安・力尽き回数
- 依頼人・依頼文（本文は右側の内部スクロール領域）
- 報酬（現在の`QuestDef.rewards`／`DeliveryDef.money`をそのまま表示）
- 依頼書下部には「受注して出発」または「納品内容を確認」の操作。未解放なら灰色で理由を表示。
- `board.lane`が`promotion`なら「昇級」の札などを追加可能。キー依頼の表示有無は、現行のゲームルールを保ち、勝手に変更しない。

### D. 操作

- PC: ↑↓で移動、Enterで確定、Esc／Backspaceで1階層戻る。選択位置が見える。
- ゲームパッド: D-pad／左スティック、決定A(×)、戻るB(○)。現行操作系のボタン割当と衝突しないよう画面モード中だけ受ける。
- タッチ: 40px以上の行、重要な決定と戻るは44px以上。スクロール領域を1つに限定する。タッチの疑似hoverで勝手に受注を進めない。
- iPhone横向きの小さい高さでは、受付説明は消し、リストと依頼書のスクロールをそれぞれ独立。文字は原則11〜14px以上。
- 「里へ戻る」を固定表示し、どの階層からも閉じられる。閉じる前の選択を覚えていても、別受付の級へ持ち越さない。
- 最終受注時は**「この依頼を受注しますか？」の確認**を1回表示する。ゲーム内の既存`startHunt(q.id)`を成功時だけ呼ぶ。
- 通常の出発ではないD09は確認後も`save.deliver(d.id)`の既存の原子的な保存処理へ渡す。勝手に`startHunt`へ流さない。

## 具体的なKari接続点

1. `src/ui/base.ts`の`ReceptionViewState`へ`stage: 'stars'|'list'`を追加。 `selected`は今の`quest.id`を維持し、`stars`は選択中の星にする。
2. `BaseScreen.renderQuests()`が級不明の時は現状の4受付案内、級が確定したら`stage==='stars'`の星縦リストか`stage==='list'`の依頼縦リストを返す。
3. `receptionGroups(c, rankId, fieldHunts)`の星→依頼を変更せず再利用する。データの順・ID・解禁条件は変えない。
4. 現行`BaseScreen.renderReceptionDetail(pane, entry)`と`renderDeliveryDetail`を右ペインに呼ぶようにする。**DOMイベントの出発・保存処理を複製しない**。現状は左ペイン内に描いているため、右ペインを新設して移動する。
5. `openStoryQuest`からの遷移では対応する受付と星と選択行が揃った状態のリストを開き、受付が違う場合は今と同じく案内を出す。
6. `setOpen`や`host.save.onChange`の再描画でも`stage`・`facilityId`・`stars`・`selected`を失わない。スクロールの記録は実際に表示されるペインのみ。
7. `src/ui/style.css`の`.reception-stars`を新しい`.quest-level-list`へ、`.reception-row`を薄い行`.quest-classic-row`へ変更。今の装備箱や工房のスタイルへ影響させないよう`#base[data-section="quest"]`配下に限定する。

## 見た目（原作を複製しない）

- 暗めの木・石の枠、黄ばんだ紙、金属留め具、霧境の文様。Kariの既存ボード・装備画・里の素材と統一。
- 大きな星と1行の依頼名が主役。現在の「色が濃くて横に広いカード」は使わない。
- アイコンはキャラクター原画の縮小表示でもよいが、量産時は128×128px程度の専用単色シルエットを用意すると一覧が締まる。まだ制作済みとは扱わない。
- 原作PSPのメニュー画像・ロゴ・装飾・音声・文章をそのまま取り込まない。

## 保全事項

- 既存4受付・rankId・星1〜8・すべての依頼ID・クエストの目標・依頼文・報酬・時間・進行条件を**変更しない**。
- 未解放の行は非表示にしない。条件付きで押せないが、内容は読める。
- `?hub=menu`では4受付へ入るための級の選択を残す。`?hunt=arena`では従来の採集除外を維持。
- チュートリアル、図鑑、物語の導線を消さない。
- 他のプレイヤーが貼る掲示板やマルチプレイ、契約金は今のKariに存在すると仮定しない。

## 進め方の優先順位

P0: 星縦選択 → 依頼名縦一覧 → 右依頼書 → 既存の出発・納品へ接続。
P1: PSP風のキー操作・戻るの統一、選択履歴、iPhone横向きの収まり。
P2: Kari固有の装飾・専用モンスター小シルエット・決定音。現在の仮音源や未採用原画の正式採用とは切り分ける。
