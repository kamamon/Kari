- 【別資料】アイテムと装備は各800枠から開始 https://w.atwiki.jp/mhp2g/pages/15.html

## 2. 現状との差分
- src/save/profile.ts SaveDoc.items は個数辞書で収納位置・容量なし。pouchOf は全道具を携帯上限まで自動選択。buy は shop.holdMax、settleRun は MAX_COUNT を上限に一括加算。装備は定義IDの配列。
- src/game/hubLife.ts chosenPouch は指定数を在庫から算出。src/data/hubLife.ts sets は3組、pouch は個数指定で実体ではない。
- src/ui/base.ts chest は武器選択・防具選択と在庫テキスト、src/ui/hubLife.ts home は3組のセットと道具の個数指定。
- src/app.ts sim開始時に chosenPouch、src/game/sim.ts は支給品自動付与＋自前品を上限まで追加。結果は app.ts settleRewards から自動保存、src/ui/result.ts は報酬表示のみ。

## 3. UI/操作契約
自室の大箱のトップを「しまう／取り出す／箱内調合／装備変更／整頓／売却／外見」に変更。装備変更は武器＋5部位、装備箱の個体一覧、能力比較、技能・耐性、20組の登録・呼び出し・編集。小型箱は集会所・農場・商店近く、同じ在庫へ接続（装備・外見変更不可）。現状の chest の機能は消さず新メニューの配下に配置する。新しい箱の位置は施設の当たり・床高さを確認してから設置。
横長画面：左にメニュー、中央に10×10のアイコン枠（ページ切替）、右に選択情報（名前、説明、希少度、所持数、携帯上限、用途）、下または左側にポーチ8枠×3ページ。100枠を一度に描画、1,000要素を常時生成しない。iPhone横画面は画面を全スクロールせずアイコン枠と詳細領域を確保、押下領域を確保、L/R相当のタッチボタン・キーボード/既存入力マップに接続。タップで選択、決定で数量（1/最大/±）、確認で保存、戻るで未確定取消。長押しで連続個数指定。整頓は同一IDを99個まで詰め直し、種類・定義順で安定ソート、手動交換は空枠も含める。選択のページ、枠、フォーカスを保存成功後も保持する。空枠は空、未知IDは「未収録」として消さない。既存アイコンを利用、見た目はKariの木・真鍮・青灰色に統一。

## 4. データ・経済の統合手順（P0）
保存を新schemaへ更新し旧版からの読み戻しで物品消失が起きないよう旧版書き込みを拒絶。boxState={version,pages,box,pouch,overflow}（参照実装）。boxStateを唯一の物品正本とし、doc.itemsは箱内個数の互換投影に限定し、全書き込みを共通APIに置換。二重の独立した書き込み禁止。移行時は旧 items から旧 chosenPouch の量を実体化し、24枠超過は箱へ、99個ずつ配置、800枠超は移行保留に保存（容量拡張等で回収、販売や調合に使用不可、消去禁止）。未知IDは保持。旧 hubLife.pouch の自動設定と3セットの道具指定は廃止、既存セットの武具は保持し道具指定は別の移行記録に残す。新規プレイは空ポーチ。
携帯上限は content.items carryMax を優先し、materials にも個別の carryMax を設計（不明品は持ち出し不可、既存素材は暫定99を設定して調整）。1種類1ポーチ枠。銃系の専用枠は実装時に原作版別に再確認、先行追加しない。
箱内調合は既存 MIXES と原価/消費ルールを使用、同じ取引で原料減算と成果物加算を行う。複数回調合は1回ずつ、満杯・不足なら停止。調合成功率の原作数値はコピーせず、現行の確定成功レシピを優先、将来成功率追加時は調合書/失敗生成物/乱数保存を別途設計。商店は購入先（ポーチ/箱）を明示、売却元（ポーチ/箱）も明示。工房は箱内素材を直接使用。農場・釣り・虫・採掘・探索・行商・家畜・里の納品・支給の全入出庫に共通APIを使い、満杯時は受取保留または明示の取消（無断破棄なし）。箱拡張2段階は専用のKariの商店品を追加、購入と100枠追加を同一保存。価格は既存経済からClaudeが設定。
SaveManager.commit の既存revisionと処理済みrunIdを使い、連打・別タブ・失敗時の再試行に対応。容量・所持・価格・設置場所を保存側で再検証する。UIは成功保存後に更新。saveDb/エクスポート/インポート/旧版移行/未知IDと整合性検証を追加。参照実装は保存器自体を含まない。

## 5. 狩猟ループ（P1）
出発前：実体ポーチの24枠をそのままコピーして出発、支給品のために自前品を勝手に置いていかない。支給箱は野営地の既存配置と接続し、自前品と区別した手動取得・数量・携帯上限をチェック、未取得はそのまま。支給限定品は帰還時に回収する。狩場の任意収納・装備変更禁止。採取/剥ぎ取り/採掘/捕獲/調合/納品はポーチまたは報酬の種類を正しく区別し、持ち切れない素材は選択して交換・捨てる・諦める（確認）。支給品や採取品の provenance は同IDでも分離（消費順の仕様を決め、支給残を在庫に混入させない）。
成功時：ポーチに残った自前品＋持帰り可能な現地素材はポーチに反映、依頼報酬は受取画面で「ポーチ／箱へ送る／売却」を選び、全受取・全箱送りの補助を置く。既存 result.ts の入手元表示とクリア回数は維持。報酬満杯は受取未確定のまま戻って整理/売却選択でき、runIdで二重受取を防ぐ。失敗時は自前消費を精算し報酬なし（既存方針）。リタイア時の自前品復元は2G準拠の候補で実機確認後採用、現在は消費扱いなので必ず別の終了種別を作る。参照 settle は「開始時の物品状態＋消費差分・持帰り差分・箱送り差分」を一括反映する例で、支給品/現地調合/クエスト中断の永続化/報酬金とクリアの更新は統合側の責務。報酬画面に持帰り素材と報酬が重複して集計されないようh.loot と rewards を分類。
出発中に別タブで箱を変更できないようrunの予約またはrevisionロック、再起動時の回復規則を設ける。保存中に出発不可。

## 6. 装備箱（P2）
物品箱とは独立した800→1000枠のKari案（最大の原作値要再確認）。装備1個=1枠。長期的に個体ID（defId, instanceId, 強化値, 装飾スロット, 装備状態）へ移す。現在の定義ID配列は移行で個体IDへ1:1変換し既存装備・お気に入り・展示・マイセット参照を更新。現行の同一定義1個制限は個体モデルと同時に見直す。生産は空枠、強化は同一個体の定義変更、装備中売却不可、売却で消えるセットは警告（無効化/解除）、20組の保存は装備のみ。技能・耐性は既存computeGearを使う。将来装飾具実装と調整。装備個体機構は参照JS未実装。
