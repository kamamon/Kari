## 何を尖らせたか

単なる数値の序列にせず、物理・属性・会心・刃容量・消耗・戦闘スタミナ・防御・耐性に交換条件を作った。7武器の得手不得手、5部位への防御の偏り、共通技能の点、固有技能の発動行動と代償を各種で決めている。数値は設計値であり、実戦DPSや最終調整済みの評価ではない。

| 系列 | 見た目 | 主な性能と使い方 |
|---|---|---|
| [ガルドロス](catalog/001-galdros.md) | 左肩・左前腕・左腰の三つの大岩塊。右側は細い革 | 基礎物理1.14倍、防御1.10倍、会心−15。通常ガードで6秒間の部位補正+18/+25%、回避消費+10/+15%。刃とスタミナの消費も重い |
| [セルヴァルク](catalog/002-selvark.md) | 背肩に寝た二枚の帆、細い胴と脚 | 風1.70倍、物理0.85倍、防御0.77倍。残スタミナ45%以下の成功回避で5秒間、回復速度+12/+18%、被ダメージ+8/+12% |
| [ヌメラドン](catalog/003-numeradon.md) | 頭と前腰に浅い泥皿、横方向の耐水皮 | 水1.75倍、物理0.82倍、会心−10。同じ個体の未破壊部位へ別行動で3回命中すると5秒間、部位補正+18/+25%、刃消耗+12/+20% |
| [ミルタセア](catalog/026-miltasea.md) | 細い襟と腰後ろの低い三つの露珠袋 | スタミナ85%以上で明示的に納刀。7秒以内の次の別攻撃行動に霧属性補正+12/+16%。構えている間は被ダメージ+8/+12%、被弾で解除 |

倍率の物理基準は同じ級・同じ武器系統の旧ガルドロス値。そこへ系統別の小さな適性を掛ける。属性は同装備の旧属性値を基準にする。防具固有スキルは防具の組合せによるもので、武器単体の特性とは別に判定する。

## スキルの実装設計

共通12技能は既存仕様を基礎にし、各部位の1点を合計して最大Lv3。固有スキルは同系列の異なる2部位・4部位で成立し、級混成や2＋2＋1の組合せも扱う。武器を防具の部位数へ数えない。5部位そろえた場合の隠し加算はない。

条件、継続時間、再発動待ち、対象固定、被弾解除、効果上限を688定義に落とした。発動させた攻撃自身へ効果を戻さず、多段攻撃と遅れて届く矢の補正を同じ行動で固定する。回避入力だけでの発動、重複イベント、ガード不能武器の到達不能条件、弓への研磨要求、状態を新しく発症させていない時の誤発動も区別する。

`reference/skill-engine.ts` はこの契約を実行する独立したTypeScript参照実装。`src/game/sim.ts` 等に接続するためのアダプタと保存・HUD・計算位置は実装仕様に記した。本体のイベントをそのまま読み替えるだけでは完成しない。

## 原寸PNGの開き方

画像の大きな一括転送が停止したため、GitにはPNGの元バイト列を小さなバイナリ部分として保存した。縮小、再圧縮、形式変換は行っていない。リポジトリのルートで次を実行すると、全22枚を `art/board-01.png`〜`board-22.png` に復元する。

```bash
python3 chatgpt-inbox/equipment-specialization-20261126/reference/materialize_art.py
```

標準Pythonのみで動作し、ネットワークを使わず、各部分と完成PNGのSHA256を照合する。GitHubのページ上でPNGを直接プレビューする形式ではない。詳細、寸法、種との対応、原画と仕様の差分は [ART.md](ART.md) と各manifestに記録した。

## 再現・確認

Node.js 22以上を使う。指定commitを持たない浅いcloneでは先に `git fetch origin main` を行う。

```bash
npm ci
python3 chatgpt-inbox/equipment-specialization-20261126/reference/validate_design.py
./node_modules/.bin/tsc -p chatgpt-inbox/equipment-specialization-20261126/reference/tsconfig.json
node --experimental-strip-types --test chatgpt-inbox/equipment-specialization-20261126/reference/*.test.ts
python3 chatgpt-inbox/equipment-specialization-20261126/reference/materialize_catalog.py --output /tmp/kari-equipment-specialization.json
python3 chatgpt-inbox/equipment-specialization-20261126/reference/materialize_art.py
```

分割JSONのままでも全データを読める。`materialize_catalog.py` は扱いやすい単一JSONへまとめるだけで、ゲーム用データへ書き込まない。`generate_catalog.py` は固定commitの入力と86種の設計を使い、同じ分割データを再生成する。
