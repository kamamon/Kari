# 防具スキルと武器特性：実装仕様

## 1. 採用する仕組み

現行の共通12技能をそのまま基礎にし、各モンスター系列に固有防具技能を1つ追加する。単なる攻撃力の上乗せではなく、その獣の器官・習性に合う行動を選んだ時に短い得意時間を作る。全86種の名称、条件、数値、解除条件は `data/species/`、実行用の688定義は `data/mechanics/` に置く。

| 層 | 装備による決め方 | 効果 |
|---|---|---|
| 共通技能12種 | 各防具1点、同じID＋対象パラメータを合算、最大Lv3 | 既存の安定した役割 |
| 防具固有86種 | 同系列の異なる2部位でLv1、4部位でLv2 | 獣に由来する条件付きの役割 |
| 武器特性86主題 / 602定義 | 装備中の武器の `traitId` 1つ、Lv1固定 | 武器だけでも系列の使い味を出す |

武器は防具の部位数へ数えない。5部位目に隠し倍率は付けない。級が違っても同じ系列なら数える。2＋2＋1なら2系列のLv1、4＋1なら1系列のLv2になる。同じ部位を二重に渡しても1部位で、現行の `wornPieces` に合わせて防御の高い所持済みの有効IDを優先する。未知ID・未所持IDで点を作らない。

固有の集計は各防具に明示された `signatureId` だけを使い、返り値もこのIDをキーにする。`seriesId` だけから固有を作らない。採集系列・固有未登録の旧防具は共通技能の点を持つが、2部位や5部位そろえてもモンスター固有は発生しない。

固有技能の強さは級で変えない。上の級では基礎攻撃・属性値・防御と形状が発達する。低級混成にも意味を残しつつ、低級の防御不足は残る。未実装級の素材を現在の狩場へ無条件に出さない。

## 2. データと実行器

`Definition` は、起点イベント、必須タグ、いずれかのタグ、HP・スタミナ範囲、必要な別行動数、集計窓、再発動待ち、持続、1行動消費、対象固定、解除イベント、最大2効果を持つ。構造は `reference/skill-engine.ts`、値域は `data/design-contract.json`、全件検査は `reference/validate_design.py`。

数値の `4` は4%で、0.04ではない。会心だけは百分率の加算ポイント。HPとスタミナの条件は現在値÷最大値×100。武器の固有特性はLv1のみなので `values` の両要素は同じ。防具は `values[0]` がLv1、`values[1]` がLv2。

現在の `computeGear` は出発時の静的な装備計算である。そこへ戦闘中の可変状態を混ぜず、出発時に共通技能と固有技能の装備情報を作り、シミュレーションが `SkillEngine` を所有する。参照実装はDOM・Three.js・壁時計に依存しない。

### イベントの確定点

| イベント | 発行する時点 | 発行しない例 |
|---|---|---|
| `hit` | 実際の接触が成立した命中。補正取得はダメージ確定より前 | 空振り・入力・残像 |
| `guard` | 通常ガードの成否と消費が確定した後 | 盾を構えただけ、受け流し |
| `parry` | 護刃の受け流し、長尖槍の受け返しが成功 | 通常ガード、受け返し入力だけ |
| `dodge` | 敵の攻撃との接触を、その回避行動の無敵区間で避けた時 | 回避入力・終了、起き上がり無敵、復活無敵、地形 |
| `charge_release` | 1段以上を実際に解放した時 | 溜め保持中、0段解放 |
| `sheathe` | 明示的な納刀行動を完了し抜刀状態がtrue→falseになった時 | 採集・道具による暗黙の納刀 |
| `draw` | 抜刀を完了した時。抜刀攻撃にも同じ行動グループを使う | 同じ抜刀状態の再通知 |
| `part_break` | 部位の未破壊→破壊が確定した時 | 破壊済み部位への通常命中 |
| `status_inflicted` | 蓄積の閾値を超えて新しい状態を発症させた時 | 単なる蓄積、すでに掛かっている状態の再読込 |
| `damage_taken` | 敵の直接攻撃で非ガードHP損失が正、かつ生存している時 | 削り、DoT、自傷、死亡する一撃 |
| `item_used` | 許可した整備品の個数が実際に1以上減った時 | 回復・睡眠道具、選択、使用開始、キャンセル、弓の研磨 |

現行の許可整備品は研磨石だけ。環弓にはこの使用経路がない。`canonicalEvent` が回避・被弾・納刀・溜め・整備・新規状態発症の証拠条件を検査する。既存の広い意味の `evade` 通知をそのまま固有技能に渡さず、敵の接触判定の分岐から正しい証拠を作る。

`status_inflicted` では、状態タグは**今回発症させた状態だけ**にする。毒中の相手を新たに眠らせた際、毒発症技能まで再発動させない。`canonicalEvent` は既存の状態タグを除去して今回のタグを追加する。

通常の命中タグは命中直前の部位・状態を使う。`broken` / `unbroken`、`asleep` を今回のダメージの結果で先取りしない。`weakspot` は物理肉質0.55以上、`head` は登録された頭部。`sameTarget` は同じ**個体ID**であり、同じ部位IDではない。

### 行動・イベントの識別

イベントIDは狩猟セッション、主体、行動インスタンス、命中窓、対象、種別から一意に作る。再送時は同じID、別の確定イベントには新しいID。すでに見たIDの除外はtick更新より先に行うため、遅れて届いた重複が時間を巻き戻さない。新規イベントの逆順tickはエラー。

攻撃の `actionId` は入力名ではなく、その実行インスタンス。多段窓と放った全ての矢に同じIDを保持する。溜め解放・抜刀・それに続く攻撃も同じグループにする。長尖槍の受け返し成功から自動の反撃へ移る場合も同じグループを引き継ぎ、発動した反撃自身へ補正を付けない。

通常ガードの応答は `guard:<敵攻撃インスタンス>` のように、保持している構えではなく受けた敵の行動を識別する。同じ敵行動の多段を数え増しせず、別の敵行動は別の成功機会にする。回避は `dodge:<自分の回避インスタンス>`、受け返しは `counter:<受け返し一回のインスタンス>` を使う。名前空間を分け、攻撃のインスタンスと衝突させない。

## 3. 時間、同時発動、多段攻撃

60Hzのsimulation tickを基準とする。ヒットストップ中もsimulationが進む限り時間を進め、ポーズ中は進めない。描画fps・壁時計・画面遷移時間で計算しない。

1. 既知のイベントIDなら何も変えず終了する。
2. 時間を進め、期限を過ぎた効果と集計窓外の印を消す。
3. 命中なら、その行動の最初の命中時点で攻撃用効果の一覧を固定する。
4. 固定する時、`originActionId === actionId` の効果を必ず除外する。
5. 対象個体に合う効果を適用し、その命中が消費条件を満たす1行動消費効果だけを現在の効果から取り除く。
6. 解除イベントを処理する。印と現在効果は消すが、再発動待ちを戻さない。
7. 条件を満たす別行動を数える。必要数に達したら効果と再発動待ちを同時に開始する。

持続区間は `[開始tick, 終了tick)`、集計窓は `現在tick−記録tick < windowTicks`。再発動待ちは発動時から。待ち時間中に次回分の印をためない。対象固定の印を集めている途中で別個体へ変えた場合は印を最初からにする。

攻撃力、属性、状態、破壊、気絶、会心、刃消耗は同じ攻撃の多段と遅延した矢で同じ発動元を使う。ただし対象個体の制約と各命中の弱点会心判定は、その命中ごとに評価する。後から発動した技能は途中の矢だけに乗らない。時間切れや通常の解除後も、既に最初の命中で確定した行動の攻撃補正はその行動の終了まで保持する。

回避・ガード消費、自然回復、被ダメージ、整備時間は現在の効果だけを使い、古い攻撃の固定情報を流用しない。1行動消費効果の解除により、同時に付いている被ダメージ増加などの代償も解除する。空振りや別対象への命中では対象固定の一回効果を消費しない。

`sameTarget` の個体制約は印の集計と攻撃用補正へ適用する。回避・ガード消費、自然回復、被ダメージ、整備時間は、発動中の装備者全体への効果である。例えばNo29のガード消費軽減は発動中なら別個体から受ける攻撃にも働き、被ダメージ増加の代償も相手を選ばない。明示的な `target_change` が解除条件なら、そのイベントで現在の効果を解除する。

行動情報の回収は「本体の行動終了」と「その行動が放った全ての投射物の終了」の両方を満たしてから。行動IDを再利用しない。狩猟開始・終了、力尽き・復活、装備変更では全ての一時状態をクリアする。これらの強いリセットでは古い矢の固定情報も消す。

## 4. 効果の合算と計算位置

共通技能＋武器特性＋混成で発動中の防具固有を加算し、**最後に1回だけ**次の範囲へ収める。技能ごとに倍率を連続乗算しない。

| チャンネル | 最終範囲 | 接続先 |
|---|---:|---|
| `rawPct` | −20〜+12% | 物理項だけ |
| `elementPct` | −30〜+20% | 武器の属性項だけ |
| `statusPct` | −30〜+20% | 武器の毒・麻痺・睡眠の蓄積 |
| `partPct` | −30〜+25% | 破壊耐久・切断の蓄積だけ |
| `stunPct` | −30〜+15% | 許可された打撃が頭へ当たった時の気絶蓄積 |
| `affinityPoints` | −15〜+15pt | 武器会心に加算。正の最終会心上限60% |
| `guardCostPct` | −30〜+25% | ガード・受け返しのスタミナ消費 |
| `dodgeCostPct` | −25〜+25% | 回避・槍の跳びの消費 |
| `edgeWearPct` | −25〜+40% | 刃・打面の消耗。弓には無い |
| `staminaRecoveryPct` | −25〜+20% | 自然回復速度だけ。待ち時間は変えない |
| `incomingDamagePct` | −12〜+25% | 防御・属性耐性を含む既存被ダメージ計算の最終係数 |
| `itemUseTicksPct` | −20〜+25% | 許可整備品の使用時間だけ |

物理会心は現行の1.25倍／負会心0.75倍、1命中につき既存の乱数を1回使う。属性・状態蓄積・気絶へ会心を掛けない。破壊補正はHPダメージを増やさず、確定したダメージから計算する部位耐久・切断の経路だけに掛ける。通常怯みへ破壊補正を流用しない。既存の丸め・睡眠の起こし倍率・盾接触の属性無効・複合属性の選択は維持する。

`edgeCapacityScale` は最大100だけでなく、鋭い60・並25・鈍い0の境界にも掛ける。初期化、研磨時の回復、段階判定、HUDの割合の全てで同じ値を使う。刃消耗は「技の消耗×系列の静的消耗倍率×(1＋合算した技能%/100)」。

`combatStaminaScale` は既存の回避・跳び・ガード・受け返し・溜め維持など、戦闘の消費に掛ける。通常攻撃の多くは元が0なので、架空の通常攻撃コストを作らない。疾走、採集、道具、納刀へは適用しない。元が0なら結果も0。

## 5. 七武器への適合

602定義は86主題×7武器。武器主題をそのまま全武器へコピーしない。元の起点が使えない時は成功回避へ、溜めがない時はその武器の締め技命中へ置換する。環弓の整備起点はスタミナ80%以上での明示的な納刀完了へ置換する。

刃消耗の効果を持つ弓は同じ値の回避消費へ、ガードできない武器のガード消費は回避消費へ、打撃が無い武器の気絶は破壊蓄積へ置換する。防具固有そのものにはこの自動置換を行わず、各種の推奨武器を併記する。

`data/action-capabilities.json` は実際の技IDとタグを列挙する。例えば護刃は斬撃も締め技も持つが、締め技は突きなので「slash AND finisher」は同じ技では成立しない。単に武器内に各タグがあるかを見る判定は不可。生成器は同じ技でタグが同時に成立するかを調べ、無理な組は締め技へ適合する。今回143定義が適合を必要とした。原本と各適合理由を残している。

## 6. 保存・UI・検証

保存は所有装備IDと装備中IDを継続し、技能値・発動中効果・印・再発動待ち・攻撃の固定情報を保存しない。未知装備IDを消さないという現行の互換方針、新しい保存版を読み取り専用にする処理、素材消費と生産の原子的な更新を維持する。新たなデータ列は任意列として導入し、古い装備は静的倍率1・固有なしを既定にする。

装備箱では共通技能の各部位の点、固有の2/4部位条件、現在のLv、次Lvに必要な部位数を表示する。戦闘UIは発動中・残り秒・再発動待ち・印の数・対象固定を小さく表示する。器官の点灯は補助で、色だけで状態を区別しない。無効な武器条件や重複して上限を超えた点は説明する。未実装級は必要な級と狩場を表示して施錠する。

参照試験は18件。全688機構・774機構/Lvの発動、起点行動除外、多段と遅延矢、重複イベント、半開区間、再発動待ち、解除、対象固定、混成、合算上限、独立したダメージ項、刃とスタミナの範囲を確認する。これは実際の `sim.ts` に組み込んだ試遊の結果ではない。統合後は同じ攻撃列を30/60fpsで再生し、HP・蓄積・耐久・消費・乱数呼出数・発動履歴が一致することを確認する。
